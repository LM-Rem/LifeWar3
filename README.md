# LIFEWAR / NEXUS · 生命战争

以康威生命游戏为核心的 **2–4 人局域网实时 PVP 网页游戏**。拥有 1000×1000 战场、阵营细胞、能量、基地、节点占领、预设与自定义图案，可干预演化的卡牌、后期节点压制，以及可折叠的全屏战术界面。

## 启动

需要 **Node.js 22 或更新版本**。在本目录打开终端：

```powershell
npm install --cache .npm-cache
npm start
```

也可双击 `start.cmd`。首次运行会安装唯一的运行依赖 `ws`；后续无需外网，无 CDN、远程字体、账号或云服务。

- 本机打开 **http://localhost:3000**。
- 打开 **http://localhost:3000/library.html** 进入图案库：可像文件管理器一样逐层浏览根目录 `图案集_128/` 中的 `.cells` 图案、跨子目录搜索关键词，并把图案导入游戏的生命图谱；也可管理 `patterns.json` 中的已有图案。
- 其他玩家连接同一局域网，在浏览器打开启动日志或联机页显示的 LAN 地址，例如 `http://192.168.1.4:3000`。
- 一人创建战区、分享邀请链接或 6 位房间码；其他人加入并准备，房主启动对局。
- 可添加 AI 补齐人数，也可在首页点击「模拟训练」直接进入人机对抗。
- 保持服务器终端运行。按 Ctrl+C 停止。使用 `$env:PORT=3001; npm start` 可更改端口。
- 若其他设备访问失败，检查是否在同一网络、Wi-Fi 是否启用设备隔离，以及 Windows 防火墙是否允许 Node.js 在**专用网络**接收入站连接。无需配置公网端口转发。

## 公网对战（Ngrok 内网穿透）

本游戏是**服务器权威**架构：本机运行权威服务器，浏览器作为客户端。用 Ngrok 把本机的 HTTP 与 WebSocket 端口暴露到公网后，外网朋友通过网址即可直接游玩，**无需将游戏改造为 WebRTC P2P**。

1. 安装 [ngrok](https://ngrok.com/)，注册并完成 `ngrok config add-authtoken <token>`。
2. 启动隧道：

   ```powershell
   ngrok http 3000
   ```

3. 从启动日志复制公网地址，例如 `https://xxxx.ngrok-free.app`。
4. 让本机服务器把该地址作为「公网地址」返回（联机页会自动优先展示，复制的邀请链接也使用它）：

   ```powershell
   $env:PUBLIC_URL="https://xxxx.ngrok-free.app"; npm start
   ```

5. 把公网地址或 `https://xxxx.ngrok-free.app/?room=XXXXXX` 邀请链接发给朋友。对方浏览器打开后会自动通过 `wss://xxxx.ngrok-free.app/ws` 连接本机服务器，加入房间正常对战。

注意事项：

- 隧道地址和带宽限制取决于所用服务配置；地址变化后需更新 `PUBLIC_URL` 并重新分享。
- 战场增量随服务器演化频率广播（当前配置 20Hz），大量细胞变化会增加带宽消耗。大规模混战建议优先使用局域网。
- 页面为 HTTPS，WebSocket 自动使用 WSS，无需额外证书配置；服务器需保持运行。
- 也可在启动时设置 `$env:NGROK_URL` 作为 `PUBLIC_URL` 的别名。

## 对战规则

以下数值按当前仓库的 `config.json` 描述；内置回退默认值见后文配置表。卡牌可以临时改变这些规则。

- **演化**：当前 20 代/秒，标准 B3/S23，有界地图不环绕。存活细胞保留所属阵营，新生细胞按邻居多数继承阵营；邻居票数并列时以位置和代数确定。阵营间细胞共同参与邻居计数，不添加额外战斗死亡规则。
- **部署**：只能部署预设或自定义图案，战场不提供绘制与擦除。每个细胞消耗 1 能量，图案不可覆盖活细胞，所有活细胞必须位于己方控制的多边形分区内；可跨越相邻的己方分区。初始 120 能量、当前上限 1000；基础每代回复 0.4（20Hz 时约 8/秒），每控制一个节点每代额外 +0.2（约 +4/秒）。
- **基地**：每人一个核心，当前耐久 100。每个基地独占一个多边形分区作为初始部署领地。敌细胞进入基地半径 32 格（含边界）时被消耗，每个细胞造成 1 点伤害。地图以圆线和引线文字标出真实受击范围，随镜头精确缩放。敌方核心 28 格内禁止直接部署。
- **节点**：每局随机 **12–16 个**，采用 best-candidate 采样使其均匀散布，节点间及节点到基地的距离至少 140 格。节点在半径 16 格内持续接触唯一阵营细胞 160 代（20Hz 时约 8 秒）后被占领；争夺时进度冻结，空置时未完成进度缓慢衰减。完成占领后无需驻守，敌人可夺取。
- **地图分区**：所有节点与基地共同生成 Voronoi 多边形，完整覆盖 1000×1000 地图，**分区数 = 节点数 + 基地数**。每个节点/基地各对应一块，几何在对局内固定，占领改变整块归属。摧毁基地后其原分区中立，不重新切分地图。主地图与小地图同步显示分区。
- **扩张方式**：普通部署不能直接进入中立多边形；越界投放和播种类卡牌提供例外。先从己方领地发射滑翔机或飞船，越界接触中立节点；取得该分区后，再将其作为前进阵地。
- **淘汰**：基地归零，所属细胞清除、节点中立。最后存活者获胜；同一代全部基地同时摧毁则平局。淘汰玩家可留在战场观战。
- **不停服演化**：对局开始后没有暂停，包括编辑图案、查看帮助和断线期间。刷新当前标签会自动重连；离线 90 秒判负；主动退出立即投降。
- **休眠**：检测原地重复的周期 1–8 结构。当前清理阈值从 200 代开始，现实时间每分钟减少 20 代，最低 20 代；清理前 10 代预警。移动图案不按静止结构清理。
- **容量**：个人 6,000 容量只约束手动部署与播种道具；不限制自然出生或存活。全局数量上限已取消，最大规模由地图空间与机器性能决定。
- **自定义图案**：128×128、最多 4096 个细胞、最多保存 30 个图案。支持鼠标编辑及标准 B3/S23 RLE 导入/导出，保存在当前浏览器。战场内无法直接绘制或删除细胞。

首版按「节点推进、围绕基地的战术攻防」设计，以 10–20 分钟为平衡目标；实际时长与阵营数、图案、操作和对抗程度有关，尚未经过多台真机的长期平衡测试。AI 是基础战术练习对手，会占领节点并发射滑翔机，不能代表高水平玩家。

对局满 10 分钟后开启节点压制，从第 601 秒起按现实秒结算：每个己方节点每秒对所有敌方核心各造成 0.1 伤害；核心护盾可抵挡，多个阵营伤害叠加，同次结算可造成平局。原 `maxCells` 配置已废弃。

## 卡牌系统

发牌时间统一配置在 `public/cards.json` 的 `drawSeconds`，单位为开局后的秒数。当前仓库值为 `[60, 180, 300, 420, 540]`，即第 1、3、5、7、9 分钟；这是可编辑配置，并非固定轮次。例如改为 `[60, 180, 300, 420, 600]`，即可在第 1、3、5、7、10 分钟发牌；支持任意轮数，时间须严格递增，`[]` 表示关闭。第 1、2 轮使用 early、mid 卡池，第 3 轮起均使用 late 卡池。修改后重启服务器并刷新页面，界面提示自动同步。

每名存活玩家每轮独立获得法则、增益、道具各一张候选，30 秒内三选一。手牌无持有上限，同名卡可重复持有；选择新卡追加到手牌，超时自动追加本轮增益卡。

点击顶部战斗栏展开仓库。PC 直接拖动卡牌；触屏先单击选中，再拖动选中卡牌。法则和增益拖出仓库后播放消散动画；道具拖出后点击战场选择目标，再在目标处播放消散动画。所有卡牌均在完整动画结束后请求服务器结算；B/S 法则收到请求后还会先预告 1 秒再生效。动画和请求等待期间禁止重复出牌，失败保留手牌。选点时可用右键、Esc 或「取消选点」退出。

当前包含 30 张卡牌，其中包括三个阶段的随机法则和「阵营同化」。同名卡具有独立编号，随机变体不会混用；重连恢复手牌、待选牌与持续效果。参数统一维护在 `public/cards.json`，征召与效果按现实秒计时，服务器校验并结算；手牌与候选仅所属玩家可见。设计修正、效果表和边界规则见 [卡牌实现说明](docs/卡牌实现.md)。

新增「阵营同化」：持续 20 秒，新生细胞有己方邻居时优先归己方；多方同时激活时恢复普通归属计算。随机法则在选牌时按权重确定并展示具体 B/S，使用时不会重新随机。B/S 法则以最后生效的规则替换前者，局部法则优先；同化独立于 B/S 法则，重复施放只刷新20秒有效期。完整概率和数值见 [扩张与平衡说明](docs/扩张与平衡.md)。

## 配置入口

| 文件 | 用途 | 生效方式 |
| --- | --- | --- |
| `config.json` | 演化速度、能量、基地、节点、休眠、部署容量与节点伤害 | 重启服务器 |
| `public/cards.json` | 发牌时间、选牌期限、预告时间、卡牌效果与随机权重 | 重启服务器并刷新客户端 |

## 自定义规则配置

基础游戏规则集中在项目根目录的 `config.json` 中，无需修改代码即可调整。演化、回复、占领等规则使用「演化代数」；节点压制、卡牌征召、卡牌效果持续时间和休眠阈值衰减使用现实时间，不随 `hz` 改变。以下为内置默认值示例，当前对局以本地 `config.json` 为准：

```json
{
  "size": 1000,
  "hz": 10,
  "dormancyGenerations": 600,
  "dormancyWarning": 100,
  "minDormancyGenerations": 100,
  "dormancyDecayPerMinute": 0,
  "nodeCountMin": 12,
  "nodeCountMax": 16,
  "baseHitRadius": 12,
  "captureRadius": 10,
  "captureTime": 30,
  "captureDecay": 0.05,
  "maxEnergy": 180,
  "regen": 0.5,
  "nodeRegen": 0.1,
  "baseHP": 240,
  "nodeDamageStartSeconds": 600,
  "nodeDamagePerSecond": 0.1,
  "playerCells": 6000,
  "deployCooldown": 1,
  "disconnectGenerations": 900,
  "roomIdleGenerations": 900
}
```

各配置项含义（括号内为默认 `hz = 10` 时的实际时间）：

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `size` | `1000` | 战场边长，地图为 `size × size` 格，有界不环绕 |
| `hz` | `10` | 每秒演化代数，即服务器主循环频率 |
| `dormancyGenerations` | `600` | 静止结构（含低周期振荡）持续多少代后被休眠清理（= 60 秒） |
| `dormancyWarning` | `100` | 休眠清理前多少代发出「休眠结构消散」警告（= 10 秒） |
| `minDormancyGenerations` | `100` | 休眠清理阈值衰减下限，可为 0 |
| `dormancyDecayPerMinute` | `0` | 每现实分钟降低的休眠阈值代数，0 为不衰减 |
| `nodeCountMin` | `12` | 每局随机节点数下限 |
| `nodeCountMax` | `16` | 每局随机节点数上限 |
| `baseHitRadius` | `12` | 敌方细胞进入基地多少格范围内会被消耗并造成伤害 |
| `captureRadius` | `10` | 节点被占领的接触半径（格） |
| `captureTime` | `30` | 节点被唯一阵营细胞持续接触多少代后完成占领（= 3 秒） |
| `captureDecay` | `0.05` | 空置节点每代进度衰减量 |
| `maxEnergy` | `180` | 每名玩家的能量上限 |
| `regen` | `0.5` | 每代基础能量回复（= 每秒 5） |
| `nodeRegen` | `0.1` | 每占领一个节点，每代额外能量回复（= 每秒 +1） |
| `baseHP` | `240` | 基地（核心）耐久值 |
| `nodeDamageStartSeconds` | `600` | 节点压制开始时间，现实秒 |
| `nodeDamagePerSecond` | `0.1` | 每个己方节点每秒对每个敌方核心造成的伤害 |
| `playerCells` | `6000` | 每名玩家的部署容量上限，不影响自然演化 |
| `deployCooldown` | `1` | 部署冷却所需代数（= 0.1 秒） |
| `disconnectGenerations` | `900` | 保留字段；当前服务器实际使用固定现实时间 90 秒 |
| `roomIdleGenerations` | `900` | 保留字段；当前无人房间按固定现实时间 90 秒清理 |

- 只写需要修改的项即可，其余使用内置默认值；删除 `config.json` 即完全恢复默认。
- `hz`、`regen`、`nodeRegen`、`captureDecay`、`nodeDamageStartSeconds`、`nodeDamagePerSecond` 允许小数，其余按整数处理；`minDormancyGenerations` 与 `dormancyDecayPerMinute` 允许为 `0`。
- 数值自动校验：非法值忽略并回退默认；`nodeCountMin > nodeCountMax` 时整组回退默认。
- 休眠阈值衰减：对局开始（服务器创建对局）时以 `dormancyGenerations` 为初始值，按现实时间每满 1 分钟减少 `dormancyDecayPerMinute` 代，但不低于 `minDormancyGenerations`。例如 `dormancyGenerations: 600`、`dormancyDecayPerMinute: 50`、`minDormancyGenerations: 100` 时，开局为 600 代，第 1 分钟降至 550 代，第 10 分钟降至 100 代，此后保持下限。`hz` 不影响该衰减节奏（按现实分钟而非代数计）。
- 修改 `hz` 会等比例改变所有代次驱动规则的**实际时间**（例如 `hz: 20` 时能量回复翻倍为每秒 10、占领 30 代仅需 1.5 秒），网络增量流量也随之成倍增加。
- `baseHitRadius` 会随开局规则同步到客户端受击圈；普通部署另有固定 28 格禁区，生成类道具使用 `max(28, baseHitRadius)` 核心保护半径。
- 地图协议、客户端和出生点按 1000×1000 设计，`size` 暂应保持 `1000`。
- `maxCells` 已废弃，不再读取。个人 `playerCells` 只影响部署，不影响自然演化。
- 配置在服务器启动时读取，修改后需**重启服务器**生效。

## 技术实现

```
浏览器 / Canvas 2D ← WebSocket ← Node.js 权威房间服务器
                              └─ 1000² 类型数组 + 稀疏邻域演化
```

- 使用 `Uint8Array` 保存世界、邻居计数；打包邻居阵营票数；只遍历活细胞及其邻域，无百万格邻居全扫描。
- `public/territory.js` 由服务器与浏览器共享：半平面裁剪生成多边形，最近站点判定处理归属；边界平票使用同一站点顺序。几何仅在开局/重连时计算，实时同步仍仅传节点归属与细胞变化。
- 服务器按 `config.json` 的 `hz` 判定规则（当前 20Hz），客户端通过 `requestAnimationFrame` 渲染镜头、界面与动效。离屏像素图层缓存细胞，避免每帧重建全部格子。
- 初次进入与重连发送完整活细胞快照；正常每代发送二进制增量，单变化格占 4 字节。状态信息 5 Hz 更新。
- 同一房间的所有客户端消费同一份权威状态，不要求浏览器各自执行模拟。服务器验证坐标、范围、碰撞、能量、容量及房主权限。
- 心跳检测、90 秒重连窗口、慢连接积压后快照恢复、请求限流、16 KB 消息上限、最多 6 房间 / 64 连接。
- 全局房间状态只在内存中。服务器重启会结束全部对局。重连令牌保存在当前标签的 `sessionStorage`；自定义图案和设置保存在 `localStorage`。
- 适用于可信局域网，不包含公网账号、排名、匹配、持久化战绩或公网安全网关。

## 2026-09-24 性能优化阶段结果

T05/T06/T10/T11 已实现有序复用缓冲、增量休眠、批量纹理更新与保序小地图缓存。相对 T04，三组合成服务端负载的平均 step+packet 耗时下降约 24% / 45% / 28%；密集高变化场景仍需约 64ms，尚未达到 20Hz。浏览器缓存改善稳定与局部变化场景，密集全图重绘仍超预算。完整范围、测试、内存代价与复现命令见 [实施与测试结果](docs/performance/t05-t11-results.md)。

`LIFEWAR_DORMANCY=legacy` 可在新游戏中恢复每代全量休眠指纹扫描；默认 `auto`，不修改游戏规则。

## 2026-09-24 T07/T08/T12 阶段结果

已加入规则/几何/预览缓存、保序 sparse/dense 演化后端，以及每次 RAF 最多应用一代的有界呈现队列。`LIFEWAR_EVOLUTION=auto|sparse|dense` 可选择后端；auto 当前使用 sparse，dense 未通过实测晋级门槛。队列超限或标签恢复会明确请求快照并记录新的恢复区间，不伪造丢失代已经绘制。

相对上一阶段，三组合成服务端负载平均耗时下降约 31% / 31% / 22%；高变化场景平均约 49ms，但仍有超期。启动排队、真实频率和跨设备实时认证仍有限制，详见 [实施与测试报告](docs/performance/t07-t12-results.md)。

## 2026-09-24 T11 密集重绘续优化

小地图密集更新复用背景与画布存储，预生成颜色并减少连续同色设置，保留逐格绘制顺序与原有调度频率。五轮浏览器对照中，50 万细胞/50 万变化的四阵营场景，更新至强制完成绘制的平均耗时从 290.1ms 降至 255.6ms（11.9%）；仍未达到 33ms 预算。123 项测试与 212 项画面像素对比通过。详情见 [实施报告](docs/performance/t11-dense-redraw-results.md)，复测入口为 `npm run benchmark:minimap`。
