# LIFEWAR / NEXUS · 生命战争

以康威生命游戏为核心的 **2–4 人局域网实时 PVP 网页游戏**。拥有 1000×1000 战场、阵营细胞、能量、基地、节点占领、预设与自定义图案，以及可折叠的全屏战术界面。

## 启动

需要 **Node.js 22 或更新版本**。在本目录打开终端：

```powershell
npm install --cache .npm-cache
npm start
```

也可双击 `start.cmd`。首次运行会安装唯一的运行依赖 `ws`；后续无需外网，无 CDN、远程字体、账号或云服务。

- 本机打开 **http://localhost:3000**。
- 打开 **http://localhost:3000/library.html** 进入图案库：可像文件管理器一样逐层浏览根目录 `图案集_128/` 中的 `.cells` 图案、跨子目录搜索关键词，并把图案导入游戏的生命图谱；也可管理 `patterns.json` 中的已有图案。
- 其他玩家连接同一局域网，在浏览器打开启动日志或联机页显示的 LAN 地址，例如 `http://192.168.1.4:3000`。
- 一人创建战区、分享邀请链接或 6 位房间码；其他人加入并准备，房主启动对局。
- 可添加 AI 补齐人数，也可在首页点击「模拟训练」直接进入人机对抗。
- 保持服务器终端运行。按 Ctrl+C 停止。使用 `$env:PORT=3001; npm start` 可更改端口。
- 若其他设备访问失败，检查是否在同一网络、Wi-Fi 是否启用设备隔离，以及 Windows 防火墙是否允许 Node.js 在**专用网络**接收入站连接。无需配置公网端口转发。

## 公网对战（Ngrok 内网穿透）

本游戏是**服务器权威**架构：本机运行权威服务器，浏览器作为客户端。用 Ngrok 把本机的 HTTP 与 WebSocket 端口暴露到公网后，外网朋友通过网址即可直接游玩，**无需将游戏改造为 WebRTC P2P**。

1. 安装 [ngrok](https://ngrok.com/)，注册并完成 `ngrok config add-authtoken <token>`。
2. 启动隧道：

   ```powershell
   ngrok http 3000
   ```

3. 从启动日志复制公网地址，例如 `https://xxxx.ngrok-free.app`。
4. 让本机服务器把该地址作为「公网地址」返回（联机页会自动优先展示，复制的邀请链接也使用它）：

   ```powershell
   $env:PUBLIC_URL="https://xxxx.ngrok-free.app"; npm start
   ```

5. 把公网地址或 `https://xxxx.ngrok-free.app/?room=XXXXXX` 邀请链接发给朋友。对方浏览器打开后会自动通过 `wss://xxxx.ngrok-free.app/ws` 连接本机服务器，加入房间正常对战。

注意事项：

- 免费版 ngrok 每次启动域名随机；需要固定域名可升级套餐，改用 `ngrok http --domain=你的域名 3000`。
- ngrok 免费带宽有限，游戏流量为服务器 10 Hz 广播；大规模混战或对延迟敏感时仍推荐同一局域网游玩。
- 页面为 HTTPS，WebSocket 自动使用 WSS，无需额外证书配置；服务器需保持运行。
- 也可在启动时设置 `$env:NGROK_URL` 作为 `PUBLIC_URL` 的别名。

## 标准规则

- **演化**：10 代/秒，标准 B3/S23，有界地图不环绕。存活细胞保留所属阵营，新生细胞按邻居多数继承阵营；三方平票以位置和代数确定。阵营间细胞共同参与邻居计数，不添加额外战斗死亡规则。
- **部署**：只能部署预设或自定义图案，战场不提供绘制与擦除。每个细胞消耗 1 能量，图案不可覆盖活细胞，所有活细胞必须位于己方控制的多边形分区内；可跨越相邻的己方分区。初始 120 能量、上限 180，回复 5/秒，每控制一个节点额外 +1/秒。
- **基地**：每人一个核心，耐久 240。每个基地独占一个多边形分区作为初始部署领地。敌细胞进入基地半径 12 格时消耗并造成 3 点伤害，每代最多 15 点。地图以圆线和引线文字标出真实受击范围，随镜头精确缩放。敌方核心 28 格内禁止直接部署。
- **节点**：每局随机 **12–16 个**，采用 best-candidate 采样使其均匀散布，节点间及节点到基地的距离至少 140 格。节点在半径 10 格内持续接触唯一阵营细胞 3 秒后被占领；争夺时进度冻结，空置时未完成进度缓慢衰减。完成占领后无需驻守，敌人可夺取。
- **地图分区**：所有节点与基地共同生成 Voronoi 多边形，完整覆盖 1000×1000 地图，**分区数 = 节点数 + 基地数**。每个节点/基地各对应一块，几何在对局内固定，占领改变整块归属。摧毁基地后其原分区中立，不重新切分地图。主地图与小地图同步显示分区。
- **扩张方式**：不能直接向中立多边形投放图案。先从己方领地发射滑翔机或飞船，越界接触中立节点；取得该分区后，再将其作为前进阵地。
- **淘汰**：基地归零，所属细胞清除、节点中立。最后存活者获胜；同一代全部基地同时摧毁则平局。淘汰玩家可留在战场观战。
- **不停服演化**：对局开始后没有暂停，包括编辑图案、查看帮助和断线期间。刷新当前标签会自动重连；离线 90 秒判负；主动退出立即投降。
- **容量**：每人 6,000、全场 24,000 个活细胞。达到容量时拒绝新增部署、限制新生细胞，现有细胞继续演化。这是标准生命规则之外的服务容量约束。
- **自定义图案**：32×32、最多 256 个细胞、最多保存 30 个图案。支持鼠标编辑及标准 B3/S23 RLE 导入/导出，保存在当前浏览器。战场内无法直接绘制或删除细胞。

首版按「节点推进、围绕基地的战术攻防」设计，以 10–20 分钟为平衡目标；实际时长与阵营数、图案、操作和对抗程度有关，尚未经过多台真机的长期平衡测试。AI 是基础战术练习对手，会占领节点并发射滑翔机，不能代表高水平玩家。

## 卡牌系统

对局第 3、5、7 分钟进行卡牌征召，每轮提供法则、增益、道具各一张，30 秒内选择。手牌上限一张；选择新卡会替换旧卡，超时保留旧卡，无手牌时自动选择增益卡。

点击顶部战斗栏展开仓库。PC 直接拖动卡牌；触屏先单击选中，再拖动选中卡牌。法则和增益拖出仓库即使用；道具拖出后点击战场选择目标，右键、Esc 或「取消选点」退出。

当前包含 26 张卡牌。参数统一维护在 `public/cards.json`，征召与效果按现实秒计时，服务器校验并结算；手牌与候选仅所属玩家可见。设计修正、效果表和边界规则见 [卡牌实现说明](docs/卡牌实现.md)。

## 自定义规则配置

基础游戏规则集中在项目根目录的 `config.json` 中，无需修改代码即可调整。演化、回复、占领等规则使用「演化代数」；卡牌征召、卡牌效果持续时间和休眠阈值衰减使用现实时间，不随 `hz` 改变。以下为内置默认值示例，当前对局以本地 `config.json` 为准：

```json
{
  "size": 1000,
  "hz": 10,
  "dormancyGenerations": 600,
  "dormancyWarning": 100,
  "minDormancyGenerations": 100,
  "dormancyDecayPerMinute": 0,
  "nodeCountMin": 12,
  "nodeCountMax": 16,
  "baseHitRadius": 12,
  "captureRadius": 10,
  "captureTime": 30,
  "captureDecay": 0.05,
  "maxEnergy": 180,
  "regen": 0.5,
  "nodeRegen": 0.1,
  "baseHP": 240,
  "maxCells": 24000,
  "playerCells": 6000,
  "deployCooldown": 1,
  "disconnectGenerations": 900,
  "roomIdleGenerations": 900
}
```

各配置项含义（括号内为默认 `hz = 10` 时的实际时间）：

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `size` | `1000` | 战场边长，地图为 `size × size` 格，有界不环绕 |
| `hz` | `10` | 每秒演化代数，即服务器主循环频率 |
| `dormancyGenerations` | `600` | 静止结构（含低周期振荡）持续多少代后被休眠清理（= 60 秒） |
| `dormancyWarning` | `100` | 休眠清理前多少代发出「休眠结构消散」警告（= 10 秒） |
| `nodeCountMin` | `12` | 每局随机节点数下限 |
| `nodeCountMax` | `16` | 每局随机节点数上限 |
| `baseHitRadius` | `12` | 敌方细胞进入基地多少格范围内会被消耗并造成伤害 |
| `captureRadius` | `10` | 节点被占领的接触半径（格） |
| `captureTime` | `30` | 节点被唯一阵营细胞持续接触多少代后完成占领（= 3 秒） |
| `captureDecay` | `0.05` | 空置节点每代进度衰减量 |
| `maxEnergy` | `180` | 每名玩家的能量上限 |
| `regen` | `0.5` | 每代基础能量回复（= 每秒 5） |
| `nodeRegen` | `0.1` | 每占领一个节点，每代额外能量回复（= 每秒 +1） |
| `baseHP` | `240` | 基地（核心）耐久值 |
| `maxCells` | `24000` | 全场活细胞容量上限 |
| `playerCells` | `6000` | 每名玩家的活细胞容量上限 |
| `deployCooldown` | `1` | 部署冷却所需代数（= 0.1 秒） |
| `disconnectGenerations` | `900` | 断线判负所需代数（= 90 秒） |
| `roomIdleGenerations` | `900` | 房间无人在线超过多少代后清理（= 90 秒） |

- 只写需要修改的项即可，其余使用内置默认值；删除 `config.json` 即完全恢复默认。
- `hz`、`regen`、`nodeRegen`、`captureDecay` 允许小数，其余按整数处理；`minDormancyGenerations` 与 `dormancyDecayPerMinute` 允许为 `0`。
- 数值自动校验：非法值忽略并回退默认；`nodeCountMin > nodeCountMax` 或 `playerCells > maxCells` 时整组回退默认。
- 休眠阈值衰减：对局开始（服务器创建对局）时以 `dormancyGenerations` 为初始值，按现实时间每满 1 分钟减少 `dormancyDecayPerMinute` 代，但不低于 `minDormancyGenerations`。例如 `dormancyGenerations: 600`、`dormancyDecayPerMinute: 50`、`minDormancyGenerations: 100` 时，前 10 分钟为 600 代，之后每分钟递减 50 代，18 分钟后稳定在 100 代。`hz` 不影响该衰减节奏（按现实分钟而非代数计）。
- 修改 `hz` 会等比例改变所有代次驱动规则的**实际时间**（例如 `hz: 20` 时能量回复翻倍为每秒 10、占领 30 代仅需 1.5 秒），网络增量流量也随之成倍增加。
- `baseHitRadius` 调整后浏览器端基地受击圈仍按代码内常量绘制，建议保持默认。
- 配置在服务器启动时读取，修改后需**重启服务器**生效。

## 技术实现

```
浏览器 / Canvas 2D ← WebSocket ← Node.js 权威房间服务器
                              └─ 1000² 类型数组 + 稀疏邻域演化
```

- 使用 `Uint8Array` 保存世界、邻居计数；打包邻居阵营票数；只遍历活细胞及其邻域，无百万格邻居全扫描。
- `public/territory.js` 由服务器与浏览器共享：半平面裁剪生成多边形，最近站点判定处理归属；边界平票使用同一站点顺序。几何仅在开局/重连时计算，实时同步仍仅传节点归属与细胞变化。
- 服务器固定 10 Hz 判定规则，客户端通过 `requestAnimationFrame` 渲染镜头、界面与动效。离屏像素图层缓存细胞，避免每帧重建全部格子。
- 初次进入与重连发送完整活细胞快照；正常每代发送二进制增量，单变化格占 4 字节。状态信息 5 Hz 更新。
- 同一房间的所有客户端消费同一份权威状态，不要求浏览器各自执行模拟。服务器验证坐标、范围、碰撞、能量、容量及房主权限。
- 心跳检测、90 秒重连窗口、慢连接积压后快照恢复、请求限流、16 KB 消息上限、最多 6 房间 / 64 连接。
- 全局房间状态只在内存中。服务器重启会结束全部对局。重连令牌保存在当前标签的 `sessionStorage`；自定义图案和设置保存在 `localStorage`。
- 适用于可信局域网，不包含公网账号、排名、匹配、持久化战绩或公网安全网关。

## 验证

```powershell
npm test
npm run benchmark
```

`npm test` 覆盖标准生命演化、能量、节点、基地攻防、平局、增量同步、RLE 及真实四客户端联机；另外验证 120 张随机地图的节点数/间距/面积覆盖、分区数、共享边界、整区转移、跨区部署原子性、前后端归属一致、12 格受击边界及 AI 越界占领。

初版 25 节点地图的本机基准（2026-09-16，Node.js 24，单房间，100 次计时；新版本可用上方命令重新测量）：

| 场景 | 活细胞 | 平均每代 | P95 每代 |
| --- | ---: | ---: | ---: |
| 分离稳定方块 | 2,000 | 0.18 ms | 0.23 ms |
| 分离稳定方块 | 9,952 | 0.57 ms | 0.77 ms |

浏览器已手动验收开始页、训练、图案部署、R/E 变换、节点占领、能量增益、RLE 编辑与保存、刷新重连；详见 `docs/verification.md`。

## 项目结构

```
public/             无构建步骤的浏览器 ES modules、界面与样式
  app.js            页面、联机客户端、输入、图案实验室
  renderer.js       Canvas 战场、小地图与首页动态球体
  patterns.js       预设、变换和 RLE
  patterns.json     生命图谱数据（图案库可浏览/新增/编辑/删除）
  territory.js      随机节点、Voronoi 分区与共享归属判定
  library.html      图案库页面：图案集目录浏览与生命图谱管理
  library.js        图案库逻辑：逐层目录、遍历子目录搜索、.cells 解析与预览
src/engine.js       权威模拟与玩法规则
src/server.js       HTTP / WebSocket、房间、重连；/api/library 图案集浏览与搜索
src/bots.js         基于领地的 AI 发射与推进
图案集_128/         .cells 图案源文件库（按 16x16 等尺寸分层存放，供图案库浏览/搜索）
tests/              规则测试、多人集成测试与性能基准
docs/plans/         设计与实施记录
```

开发时运行 `npm run dev` 自动重启服务器；前端文件修改后刷新即可。后端重启会清除现有房间。
