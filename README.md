# LIFEWAR / NEXUS · 生命战争

以康威生命游戏为核心的 **2–4 人局域网实时 PVP 网页游戏**。拥有 1000×1000 战场、阵营细胞、能量、基地、节点占领、预设与自定义图案，可干预演化的卡牌、后期节点压制，以及可折叠的全屏战术界面。

## 启动

需要 **Node.js 22 或更新版本**。在本目录打开终端：

```powershell
npm install --cache .npm-cache
npm start
```

也可双击 `运行.bat`。`npm start`、`npm run dev` 和双击脚本默认启用 **房间线程隔离＋GPU 演化＋v2 紧凑棋盘协议**；显式设置的环境变量优先。首次运行会安装运行依赖 `ws`，并尝试安装可选 GPU 依赖 `webgpu`；旧安装升级后请先执行一次 `npm install --cache .npm-cache`。GPU 依赖或设备不可用时在房间线程内自动回退 CPU，v2 仍保持启用。后续无需外网，无 CDN、远程字体、账号或云服务。

- 本机打开 **http://localhost:3000**。
- 打开 **http://localhost:3000/library.html** 进入图案库：可像文件管理器一样逐层浏览根目录 `图案集_128/` 中的 `.cells` 图案、跨子目录搜索关键词，并把图案导入游戏的生命图谱；也可管理 `patterns.json` 中的已有图案。
- 其他玩家连接同一局域网，在浏览器打开启动日志或联机页显示的 LAN 地址，例如 `http://192.168.1.4:3000`。
- 一人创建战区、分享邀请链接或 6 位房间码；其他人加入并准备，房主启动对局。
- 可添加 AI 补齐人数，也可在首页点击「模拟训练」直接进入人机对抗。
- 保持服务器终端运行。按 Ctrl+C 停止。使用 `$env:PORT=3001; npm start` 可更改端口。
- GPU 的 `gpu-probe.json` 仅用于初始化和首次计算探测，首次计算成功后立即清除；已正常进行游戏后直接关闭后端窗口，不会因残留标记在下次启动时停用 GPU。旧版遗留的 `stable` 标记会在下次探测时自动清理。若在初始化或首次计算完成前强行结束进程，仍会留下保护标记（无法区分驱动崩溃和手动关闭）；确认后可删除该文件重试。首次成功后的原生崩溃不再由此标记持久禁用 GPU，已知危险适配器拦截与运行时 CPU 回退继续有效。`LIFEWAR_GPU_PROBE=0` 完全关闭标记读写。
- 若其他设备访问失败，检查是否在同一网络、Wi-Fi 是否启用设备隔离，以及 Windows 防火墙是否允许 Node.js 在**专用网络**接收入站连接。无需配置公网端口转发。

## 公网对战（Ngrok 内网穿透）

本游戏是**服务器权威**架构：本机运行权威服务器，浏览器作为客户端。用 Ngrok 把本机的 HTTP 与 WebSocket 端口暴露到公网后，外网朋友通过网址即可直接游玩，**无需将游戏改造为 WebRTC P2P**。

1. 安装 [ngrok](https://ngrok.com/)，注册并完成 `ngrok config add-authtoken <token>`。
2. 启动隧道：

   ```powershell
   ngrok http 3000
   ```

3. 从启动日志复制公网地址，例如 `https://xxxx.ngrok-free.app`。
4. 让本机服务器把该地址作为「公网地址」返回（联机页会自动优先展示，复制的邀请链接也使用它）：

   ```powershell
   $env:PUBLIC_URL="https://xxxx.ngrok-free.app"; npm start
   ```

5. 把公网地址或 `https://xxxx.ngrok-free.app/?room=XXXXXX` 邀请链接发给朋友。对方浏览器打开后会自动通过 `wss://xxxx.ngrok-free.app/ws` 连接本机服务器，加入房间正常对战。

注意事项：

- 隧道地址和带宽限制取决于所用服务配置；地址变化后需更新 `PUBLIC_URL` 并重新分享。
- 战场增量随服务器演化频率广播（当前配置 20Hz），大量细胞变化会增加带宽消耗。大规模混战建议优先使用局域网。
- 页面为 HTTPS，WebSocket 自动使用 WSS，无需额外证书配置；服务器需保持运行。
- 也可在启动时设置 `$env:NGROK_URL` 作为 `PUBLIC_URL` 的别名。

## 操作

### 界面风格

在首页、联机大厅、战场或图案库打开 **设置 → 界面风格**，可切换：

- **深空战术**：原版深色科幻主题，现有浏览器默认保持此主题。
- **生命花园**：奶油白与薄荷绿的浅色圆角卡通主题，覆盖所有页面、面板、弹窗、卡牌、图案预览与编辑器；地图、分区、基地、节点、部署预览和细胞同步换装。

选择自动保存在当前浏览器，刷新、跳转图案库及同源标签页保持同步。主题只影响显示，不改变演化规则、地图坐标或对局进度。近景显示圆角糖豆细胞，远景与小地图采用同色轻量纹理，保持大范围总览的清晰度。

浏览器主题验收可使用已有 Playwright 与浏览器运行：`npm run test:browser:theme -- --playwright <模块路径> --executable <浏览器路径>`；截图与结果保存在 `artifacts/theme/`。

## 对战规则

以下数值按当前仓库的 `config.json` 描述；内置回退默认值见后文配置表。卡牌可以临时改变这些规则。

- **演化**：当前 20 代/秒，标准 B3/S23，有界地图不环绕。存活细胞保留所属阵营，新生细胞按邻居多数继承阵营；邻居票数并列时以位置和代数确定。阵营间细胞共同参与邻居计数，不添加额外战斗死亡规则。
- **部署**：只能部署预设或自定义图案，战场不提供绘制与擦除。每个细胞消耗 1 能量，图案不可覆盖活细胞，所有活细胞必须位于己方控制的多边形分区内；可跨越相邻的己方分区。初始 120 能量、当前上限 1000；基础每代回复 0.4（20Hz 时约 8/秒），每控制一个节点每代额外 +0.2（约 +4/秒）。
- **基地**：每人一个核心，当前耐久 100。每个基地独占一个多边形分区作为初始部署领地。敌细胞进入基地半径 32 格（含边界）时被消耗，每个细胞造成 1 点伤害。地图以圆线和引线文字标出真实受击范围，随镜头精确缩放。敌方核心 28 格内禁止直接部署。
- **节点**：每局随机 **12–16 个**，采用 best-candidate 采样使其均匀散布，节点间及节点到基地的距离至少 140 格。节点在半径 16 格内持续接触唯一阵营细胞 160 代（20Hz 时约 8 秒）后被占领；争夺时进度冻结，空置时未完成进度缓慢衰减。完成占领后无需驻守，敌人可夺取。
- **地图分区**：所有节点与基地共同生成 Voronoi 多边形，完整覆盖 1000×1000 地图，**分区数 = 节点数 + 基地数**。每个节点/基地各对应一块，几何在对局内固定，占领改变整块归属。摧毁基地后其原分区中立，不重新切分地图。主地图与小地图同步显示分区。
- **扩张方式**：普通部署不能直接进入中立多边形；越界投放和播种类卡牌提供例外。先从己方领地发射滑翔机或飞船，越界接触中立节点；取得该分区后，再将其作为前进阵地。
- **淘汰**：基地归零，所属细胞清除、节点中立。最后存活者获胜；同一代全部基地同时摧毁则平局。淘汰玩家可留在战场观战。
- **不停服演化**：对局开始后没有暂停，包括编辑图案、查看帮助和断线期间。刷新当前标签会自动重连；离线 90 秒判负；主动退出立即投降。
- **休眠**：检测原地重复的周期 1–8 结构。当前清理阈值从 200 代开始，现实时间每分钟减少 20 代，最低 20 代；清理前 10 代预警。移动图案不按静止结构清理。
- **容量**：个人 6,000 容量只约束手动部署与播种道具；不限制自然出生或存活。全局数量上限已取消，最大规模由地图空间与机器性能决定。
- **自定义图案**：128×128、最多 4096 个细胞、最多保存 30 个图案。支持鼠标编辑及标准 B3/S23 RLE 导入/导出，保存在当前浏览器。战场内无法直接绘制或删除细胞。

首版按「节点推进、围绕基地的战术攻防」设计，以 10–20 分钟为平衡目标；实际时长与阵营数、图案、操作和对抗程度有关，尚未经过多台真机的长期平衡测试。AI 是基础战术练习对手，会占领节点并发射滑翔机，不能代表高水平玩家。

对局满 10 分钟后开启节点压制，从第 601 秒起按现实秒结算：每个己方节点每秒对所有敌方核心各造成 0.1 伤害；核心护盾可抵挡，多个阵营伤害叠加，同次结算可造成平局。原 `maxCells` 配置已废弃。

## 卡牌系统

发牌时间统一配置在 `public/cards.json` 的 `drawSeconds`，单位为开局后的秒数。当前仓库值为 `[60, 180, 300, 420, 540]`，即第 1、3、5、7、9 分钟；这是可编辑配置，并非固定轮次。例如改为 `[60, 180, 300, 420, 600]`，即可在第 1、3、5、7、10 分钟发牌；支持任意轮数，时间须严格递增，`[]` 表示关闭。第 1、2 轮使用 early、mid 卡池，第 3 轮起均使用 late 卡池。修改后重启服务器并刷新页面，界面提示自动同步。

每名存活玩家每轮独立获得法则、增益、道具各一张候选，30 秒内三选一。手牌无持有上限，同名卡可重复持有；选择新卡追加到手牌，超时自动追加本轮增益卡。

点击顶部战斗栏展开仓库。PC 直接拖动卡牌；触屏先单击选中，再拖动选中卡牌。法则和增益拖出仓库后播放消散动画；道具拖出后点击战场选择目标，再在目标处播放消散动画。所有卡牌均在完整动画结束后请求服务器结算；B/S 法则收到请求后还会先预告 1 秒再生效。动画和请求等待期间禁止重复出牌，失败保留手牌。选点时可用右键、Esc 或「取消选点」退出。

当前包含 30 张卡牌，其中包括三个阶段的随机法则和「阵营同化」。同名卡具有独立编号，随机变体不会混用；重连恢复手牌、待选牌与持续效果。参数统一维护在 `public/cards.json`，征召与效果按现实秒计时，服务器校验并结算；手牌与候选仅所属玩家可见。设计修正、效果表和边界规则见 [卡牌实现说明](docs/卡牌实现.md)。

新增「阵营同化」：持续 20 秒，新生细胞有己方邻居时优先归己方；多方同时激活时恢复普通归属计算。随机法则在选牌时按权重确定并展示具体 B/S，使用时不会重新随机。B/S 法则以最后生效的规则替换前者，局部法则优先；同化独立于 B/S 法则，重复施放只刷新20秒有效期。完整概率和数值见 [扩张与平衡说明](docs/扩张与平衡.md)。

## 配置入口

| 文件 | 用途 | 生效方式 |
| --- | --- | --- |
| `config.json` | 演化速度、能量、基地、节点、休眠、部署容量与节点伤害 | 重启服务器 |
| `public/cards.json` | 发牌时间、选牌期限、预告时间、卡牌效果与随机权重 | 重启服务器并刷新客户端 |
| `public/patterns.json` | 生命图谱数据 | 通过图案库管理，或修改后刷新 |

图案可设置可空的 `direction` 字段：`上`、`下`、`左`、`右`、`左上`、`右上`、`左下`、`右下`。缺省、`null` 或空字符串表示无方向。在图案库导入或编辑时选择「方向」，选择「无方向」可清除；保存后刷新游戏页面生效。生命图谱选项显示原始方向箭头，部署协议预览显示经过左右镜像、顺时针旋转后的方向箭头。旧图案不自动推断方向。

服务器可用 `LIFEWAR_CONFIG_PATH` 指定其他规则配置文件。规则配置缺项采用 `src/config.js` 的默认值；卡牌配置会严格校验，非法参数会报错。

## 自定义规则配置

基础游戏规则集中在项目根目录的 `config.json` 中，无需修改代码即可调整。演化、回复、占领等规则使用「演化代数」；节点压制、卡牌征召、卡牌效果持续时间和休眠阈值衰减使用现实时间，不随 `hz` 改变。以下为内置默认值示例，当前对局以本地 `config.json` 为准：

```json
{
  "size": 1000,
  "hz": 10,
  "dormancyGenerations": 600,
  "dormancyWarning": 100,
  "minDormancyGenerations": 100,
  "dormancyDecayPerMinute": 0,
  "nodeCountMin": 12,
  "nodeCountMax": 16,
  "baseHitRadius": 12,
  "captureRadius": 10,
  "captureTime": 30,
  "captureDecay": 0.05,
  "maxEnergy": 180,
  "regen": 0.5,
  "nodeRegen": 0.1,
  "baseHP": 240,
  "nodeDamageStartSeconds": 600,
  "nodeDamagePerSecond": 0.1,
  "playerCells": 6000,
  "deployCooldown": 1,
  "disconnectGenerations": 900,
  "roomIdleGenerations": 900
}
```

各配置项含义（括号内为默认 `hz = 10` 时的实际时间）：

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `size` | `1000` | 战场边长，地图为 `size × size` 格，有界不环绕 |
| `hz` | `10` | 每秒演化代数，即服务器主循环频率 |
| `dormancyGenerations` | `600` | 静止结构（含低周期振荡）持续多少代后被休眠清理（= 60 秒） |
| `dormancyWarning` | `100` | 休眠清理前多少代发出「休眠结构消散」警告（= 10 秒） |
| `minDormancyGenerations` | `100` | 休眠清理阈值衰减下限，可为 0 |
| `dormancyDecayPerMinute` | `0` | 每现实分钟降低的休眠阈值代数，0 为不衰减 |
| `nodeCountMin` | `12` | 每局随机节点数下限 |
| `nodeCountMax` | `16` | 每局随机节点数上限 |
| `baseHitRadius` | `12` | 敌方细胞进入基地多少格范围内会被消耗并造成伤害 |
| `captureRadius` | `10` | 节点被占领的接触半径（格） |
| `captureTime` | `30` | 节点被唯一阵营细胞持续接触多少代后完成占领（= 3 秒） |
| `captureDecay` | `0.05` | 空置节点每代进度衰减量 |
| `maxEnergy` | `180` | 每名玩家的能量上限 |
| `regen` | `0.5` | 每代基础能量回复（= 每秒 5） |
| `nodeRegen` | `0.1` | 每占领一个节点，每代额外能量回复（= 每秒 +1） |
| `baseHP` | `240` | 基地（核心）耐久值 |
| `nodeDamageStartSeconds` | `600` | 节点压制开始时间，现实秒 |
| `nodeDamagePerSecond` | `0.1` | 每个己方节点每秒对每个敌方核心造成的伤害 |
| `playerCells` | `6000` | 每名玩家的部署容量上限，不影响自然演化 |
| `deployCooldown` | `1` | 部署冷却所需代数（= 0.1 秒） |
| `disconnectGenerations` | `900` | 保留字段；当前服务器实际使用固定现实时间 90 秒 |
| `roomIdleGenerations` | `900` | 保留字段；当前无人房间按固定现实时间 90 秒清理 |

- 只写需要修改的项即可，其余使用内置默认值；删除 `config.json` 即完全恢复默认。
- `hz`、`regen`、`nodeRegen`、`captureDecay`、`nodeDamageStartSeconds`、`nodeDamagePerSecond` 允许小数，其余按整数处理；`minDormancyGenerations` 与 `dormancyDecayPerMinute` 允许为 `0`。
- 数值自动校验：非法值忽略并回退默认；`nodeCountMin > nodeCountMax` 时整组回退默认。
- 休眠阈值衰减：对局开始（服务器创建对局）时以 `dormancyGenerations` 为初始值，按现实时间每满 1 分钟减少 `dormancyDecayPerMinute` 代，但不低于 `minDormancyGenerations`。例如 `dormancyGenerations: 600`、`dormancyDecayPerMinute: 50`、`minDormancyGenerations: 100` 时，开局为 600 代，第 1 分钟降至 550 代，第 10 分钟降至 100 代，此后保持下限。`hz` 不影响该衰减节奏（按现实分钟而非代数计）。
- 修改 `hz` 会等比例改变所有代次驱动规则的**实际时间**（例如 `hz: 20` 时能量回复翻倍为每秒 10、占领 30 代仅需 1.5 秒），网络增量流量也随之成倍增加。
- `baseHitRadius` 会随开局规则同步到客户端受击圈；普通部署另有固定 28 格禁区，生成类道具使用 `max(28, baseHitRadius)` 核心保护半径。
- 地图协议、客户端和出生点按 1000×1000 设计，`size` 暂应保持 `1000`。
- `maxCells` 已废弃，不再读取。个人 `playerCells` 只影响部署，不影响自然演化。
- 配置在服务器启动时读取，修改后需**重启服务器**生效。

## 技术实现

```
浏览器 / Canvas 2D ← WebSocket ← Node.js 主线程（大厅、连接、转发）
                                    └─ 每房间 worker（权威结算、AI、编码、历史）
                                         ├─ Dawn / WebGPU 计算线程
                                         └─ CPU 稀疏演化回退
```

- 使用 `Uint8Array` 保存世界、邻居计数；打包邻居阵营票数；只遍历活细胞及其邻域，无百万格邻居全扫描。
- `public/territory.js` 由服务器与浏览器共享：半平面裁剪生成多边形，最近站点判定处理归属；边界平票使用同一站点顺序。几何仅在开局/重连时计算，实时同步仍仅传节点归属与细胞变化。
- 服务器按 `config.json` 的 `hz` 逐代判定规则（当前 20Hz），客户端通过 `requestAnimationFrame` 逐代呈现并渲染镜头、界面与动效。细胞使用类型数组链表和离屏像素纹理；小地图约 10Hz 缩绘纹理，保留阵营分布、领地与基地，不要求旧版像素一致。
- 初次进入与重连发送完整活细胞快照；正常每代发送独立二进制增量。运行脚本默认协商 v2：有序条目、差值与新协商自适应位图编码按完整包大小择优；新客户端不再要求细胞插入顺序，旧客户端保留原有顺序协议；旧客户端仍可使用 v1（单变化格 4 字节）。状态信息 5 Hz 更新。
- 同一房间的所有客户端消费同一份权威状态，不要求浏览器各自执行模拟。服务器验证坐标、范围、碰撞、能量、容量及房主权限。
- 心跳检测、90 秒重连窗口、慢连接逐代历史重放（每房间最多 32 代 / 16MiB，达到任一上限淘汰最旧记录），历史不足或客户端显式恢复时发送快照；不合并多代。请求限流、16 KB 消息上限、最多 6 房间 / 64 连接。
- 全局房间状态只在内存中。服务器重启会结束全部对局。重连令牌保存在当前标签的 `sessionStorage`；自定义图案和设置保存在 `localStorage`。
- 适用于可信局域网，不包含公网账号、排名、匹配、持久化战绩或公网安全网关。

## 2026-09-26 GPU、渲染与传输优化

本轮只以规则准确、逐代计算和呈现为约束，不合并代数。小地图允许近似，默认已切换纹理缩绘；客户端细胞 Map 改为类型数组链表，保留插入顺序。慢连接优先重放每一代，静态文件默认启用 gzip/ETag；单房间异常会停止该房间并提示玩家，其他房间继续。

GPU 仍属于**实验后端**，现按用户选择由运行脚本默认启用，在服务器所在电脑执行，不依赖玩家浏览器支持 WebGPU：

```powershell
npm start
```

默认启用房间线程隔离，创建对局时日志会显示该房间的实际适配器。没有兼容设备或可选依赖、设备失败、单代等待超过 100ms 时回退 CPU。2026-09-27 起 GPU 支持最多 64 个整数圆形局部法则（重叠时后添加者优先）；超过该数量或几何参数不支持时，该代回退 CPU。每代仍完整结算基地、节点、能量、卡牌及休眠，不跳代。设 `LIFEWAR_EVOLUTION=sparse` 可强制使用 CPU；移除该环境变量后通过运行脚本启动，会重新采用默认 GPU。

本机 RTX 5070 Ti Laptop / D3D12 实测：约 50 万细胞持续高变化，GPU＋v1 连续 100 代约 **19.9 代/秒**，零漏收、零漏画、零快照恢复；每代含打包/发送提交的中位数约 **43.2ms**。这是单机单浏览器短测，并不保证所有显卡、多房间或百万细胞负载稳定 20Hz。

小地图最终版本的 50万 / 80万细胞绘制提交中位数为 **0.8 / 1.0ms**，旧缓存同组对照为 **173 / 269ms**；连同快照应用和强制完成绘制约 **18.6 / 26.1ms**。图案库 JSON 由 1,882,037 字节 gzip 到 108,251 字节（减少约 **94.2%**）。

运行脚本现在默认设置 `LIFEWAR_BOARD_PROTOCOL=2`：本轮密集场景逐代数据减少约 25%，但有额外编解码成本。显式设置为 `1` 可回退旧协议。`LIFEWAR_COMPRESSION=1` 可试用 WebSocket 压缩，**默认关闭**：密集 CPU 负载下实测会积压并触发快照。静态资源 gzip 不受此开关影响。

## 性能方案与当前启动默认值

以下方案均已接入游戏。收益来自不同场景和不同阶段，不能相加；历史数据不代表所有机器都会达到相同结果。所有演化后端和协议均保持逐代处理，不以合并代数提升性能。

| 方案 | 开关与运行脚本默认值 | 已测提升 | 代价与适用范围 |
| --- | --- | --- | --- |
| GPU 演化 | `LIFEWAR_EVOLUTION=gpu`；**默认启用** | 50万／80万／100万细胞完整单代计算与打包中位耗时降低约 14.7%／19.0%／21.5%；本机50万高变化 GPU＋v1 连续100代约19.9代/秒，GPU＋v2 60代约18.0代/秒 | 需要兼容 GPU 和可选 `webgpu` 原生依赖；默认房间隔离路径中，数据搬运与同步等待已移入房间/GPU线程。小负载不保证更快，百万细胞不保证稳定20Hz。现支持最多64个整数圆形局部法则，不支持的参数、设备失败或超时回退 CPU |
| 房间线程隔离 | `LIFEWAR_ROOM_WORKERS=1`；**默认启用** | 主要改善主线程与其他房间的响应；本机GPU＋v2跨房间/同房间选卡对照见文末 | 每房间增加线程和GPU实例；同房间操作仍需等待当前代结束。保留32代/16MiB历史、有界线程输出和明确快照恢复。设为`0`回退原主线程执行 |
| 变化前沿演化 | `LIFEWAR_EVOLUTION=frontier`；默认不启用 | 历史同版对照：静物耗时降低20.8%，密集低变化扩张降低28.7%；静物海加少量局部规则的补充测试曾接近减半 | 高变化场景反而慢约2.6%；每房间额外约1.91MiB缓存。规则变化或大量细胞变化会触发重建，仍需逐代遍历候选。适合大量稳定结构、少量活动细胞 |

| v2 紧凑棋盘协议 | `LIFEWAR_BOARD_PROTOCOL=2`；**默认启用** | 50万高变化：v1约2.00MB，原v2约1.50MB，新协商差值编码约0.81MB（较原v2再省约46%）；历史80万既有细胞变色场景减少68.3% | 增加编解码、校验和顺序恢复开销，服务器增加约1MB/房间基准棋盘。历史CPU全链路约17.57→16.00代/秒；历史GPU＋v2约18.04代/秒，GPU＋v1约19.88代/秒（不同长度短测）；本轮同条件旧v2→差值扩展为19.63→17.25代/秒。空包8B→32B。优先降低带宽时使用 |
| WebSocket 消息压缩 | `LIFEWAR_COMPRESSION=1`；**默认关闭** | 已实现压缩协商，但本轮没有确认可推荐的稳定净收益，也未量化实际压缩后线缆流量 | 增加CPU和缓冲内存开销；密集测试发生严重积压，扩大缓冲后仍漏收中间代并触发4次快照恢复。仅建议轻负载、带宽受限时另行验证；与默认启用的静态资源 gzip 无关 |

GPU、frontier、dense 是互斥的演化后端；`sparse` 是 CPU 稀疏后端，`auto` 当前也固定选择 sparse，不自动选择 GPU/frontier/dense。协议和 WebSocket 压缩可以独立设置。

启动默认值由 `src/runtime-defaults.js` 提供，供 `npm start`、`npm run dev` 加载房间线程隔离＋GPU＋v2；`运行.bat` 调用同一个 `npm start`。显式环境变量优先。直接运行 `node src/server.js`、导入 `createServer()` 以及测试/基准不加载这组启动默认值，仍沿用自身参数或环境设置，避免改变基准条件；程序调用可传 `createServer({roomWorkers:true})` 启用隔离。

**强制回退 CPU＋v1：**

```powershell
$env:LIFEWAR_EVOLUTION="sparse"
$env:LIFEWAR_BOARD_PROTOCOL="1"
npm start
```

**恢复运行脚本默认 GPU＋v2：**

```powershell
Remove-Item Env:LIFEWAR_EVOLUTION -ErrorAction SilentlyContinue
Remove-Item Env:LIFEWAR_BOARD_PROTOCOL -ErrorAction SilentlyContinue
npm start
```

以上修改均在重启服务器、新建对局后生效；重启会结束内存中的现有对局。GPU＋v2成为默认是当前部署选择，不表示已有性能限制被消除。详细依据：[GPU与网络最新结果](docs/performance/2026-09-26-gpu-overview-network.md)、[frontier](docs/performance/t09-results.md)、[dense](docs/performance/t07-t12-results.md)、[v2协议](docs/performance/t13-results.md)。

## 窄带内网穿透优化（2026-09-26）

保留运行脚本默认 **GPU＋v2**，优先减少流量。新客户端自动协商 v2 有序差值编码，每个包在原编码与新编码中选择较小者；兼容旧客户端。每代独立计算、传输和呈现，不合并代数。重启服务器并刷新客户端后启用，重启会结束当前内存对局。

| 场景（20个连续采样代，中位数） | 原v2 TCP发送字节/包 | 新编码 TCP发送字节/包 | 减少 |
| --- | ---: | ---: | ---: |
| 50万高变化，每代增量 | 1,499,598 | 806,336 | 46.2% |
| 约83万细胞低变化扩张，每代增量 | 4,434 | 1,904 | 57.1% |
| 约83万细胞全量快照 | 2,483,091 | 865,512 | 65.1% |
| 2.4万静物全量快照 | 72,042 | 36,092 | 49.9% |

上述字节是实际本地 TCP socket 计数，包含 WebSocket 帧头，不含 TLS/穿透服务封装；消息压缩关闭。50万高变化增量在 Node 中编码中位数约5.30→10.91ms、解码约8.03→10.10ms。单浏览器、GPU、相同预热25代＋测量60代：旧v2→新编码约19.63→17.25代/秒，单代含状态消息的流量约1.50→0.815MB，均零漏收、零漏画、零恢复；这是用额外CPU换带宽，并非全面提速。

仍不能保证极小带宽下50万高变化实时运行：20代/秒约需16MB/s/客户端，历史缓存只解决短时抖动，长期不足仍会触发恢复。普通低变化对局小得多；不要把上述极端合成负载等同于每局流量。

同时去掉部署预览每帧整组状态的 JSON.stringify，改为相关字段比较；几何邻接关系缓存，领地查询索引按需构建行；清理小地图空钩子和废弃逐格回调。`npm run benchmark` 增加持续50万高变化档，`node tests/performance/bandwidth.mjs` 可重测编码与实际socket字节。

主图仍严格验证像素一致（156项对照），小地图验证阵营空间分布、尺寸、状态刷新、清空和重连；v1/v2 主图、顺序和当前小地图一致性另有浏览器测试。房间worker、休眠历史/清零重构、图案管理鉴权和库索引等建议的判断，见[本轮计划](docs/plans/2026-09-26-bandwidth-followup.md)与[测量及取舍](docs/performance/2026-09-26-bandwidth-followup.md)。

## 选卡优先与 GPU 局部法则（2026-09-27）

选牌、出牌、候选与手牌同步使用自动协商的独立控制 WebSocket；通过当前会话令牌绑定，主连接关闭即失效。控制连接不可用时回退主连接。卡牌状态按房间 epoch 和递增序号更新，不再等待棋盘逐代播放；地图仍逐代处理。点击候选立即显示提交中并防止重复发送，失败允许重试，不提前伪造获得卡牌。每个游戏客户端最多使用两条连接，仍受服务器总计64连接限制。

本机 Edge 无头浏览器测试中，将主连接消息人为积压1200ms，旧版／新版选卡确认约1212／288ms；控制重连与恢复后手牌一致性通过。该测试只证明绕过主连接积压，不代表真实公网延迟保证。

GPU 新增重叠局部法则计算。RTX 5070 Ti Laptop 上两个局部法则、50万／80万／100万初始细胞的单代结算＋v1打包中位数，CPU约59.1／57.2／66.8ms，GPU约44.2／41.2／49.9ms。仍有超期样本；后续房间线程隔离已将同步等待与CPU结算移出主线程，浏览器长任务尚未由该改动解决。

方案、验证范围、复现命令及限制见[实施计划](docs/plans/2026-09-27-card-priority-gpu.md)与[实施结果](docs/performance/2026-09-27-card-priority-gpu.md)。重启服务器并刷新所有客户端生效；重启会结束现有内存对局。

## 房间线程隔离（2026-09-27）

运行脚本默认启用 `LIFEWAR_ROOM_WORKERS=1`。演化、GPU等待、AI、结算、编码和历史进入每房间独立worker；主线程保留连接、大厅和消息转发。部署与卡牌在完整代数之间按顺序执行，旧会话输出不能影响重连后的连接。故障只停止所属房间；线程输出、命令数量与历史均有上限，仍保持逐代传输和明确快照恢复。

本机GPU＋v2、一个约50万细胞持续高变化房间的本地短测中，另一房间选卡P95约 **58.8→0.6ms**。高负载房间自身仍需等待当前代；增加仅在真人待选且计算超期时启用的2ms命令窗口后，30次样本最慢确认约 **50.9→4.5ms**，但P95约 **1.3→4.1ms**，该持续征召夹具的演化吞吐约 **19.2→16.2代/秒**。这是选卡响应与吞吐的取舍，不代表公网延迟或稳定20Hz认证。

设 `$env:LIFEWAR_ROOM_WORKERS='0'` 后重启可回退原主线程执行；删除该变量后重启恢复默认隔离。GPU不可用时仍在房间线程内回退CPU。每房间增加线程与GPU实例；浏览器自身的长任务及物理带宽不足不由这项改动解决。

详细设计、验收、生命周期与复现命令见[计划](docs/plans/2026-09-27-room-workers.md)及[实施结果](docs/performance/2026-09-27-room-workers.md)。启动新版本需要重启服务器，现有内存对局会结束。


## 客户端顺序解耦与自适应位图（2026-09-28）

| 场景 | 原差值扩展 TCP 字节/包 | 新自适应编码 TCP 字节/包 | 减少 |
| --- | ---: | ---: | ---: |
| 50万细胞高变化增量 | 806,336 | 260,537 | 67.7% |
| 约83万细胞低变化增量 | 1,904 | 1,904 | 0% |
| 约83万细胞快照 | 865,512 | 320,236 | 63.0% |
| 2.4万静物快照 | 36,092 | 36,092 | 0% |

20Hz 下，高变化棋盘下载需求按本次包大小换算约 **16.1→5.2MB/s/客户端**，含WebSocket帧头，不含状态JSON、TLS与穿透封装。Node编解码中位耗时约10.69/9.54→8.69/6.52ms。位图会展开整块状态；同机GPU单浏览器60代对照中，实际吞吐约17.38→19.09代/秒，均零漏收、零漏画、零恢复，但客户端应用中位耗时10.7→18.2ms，未通过严格实时门槛。这是本地短测，不保证弱设备、公网或多房间稳定20Hz。

## 发送追赶、紧凑位图应用与进度反馈（2026-09-29）

本轮保留虚拟组网和WebSocket，棋盘协议字节不变。发送缓冲释放后可继续有界重放历史，不再必须等待下一代演化；每批最多4包，累计256KiB后让出，单个合法大包仍可发送。worker输出锁与缓冲通知分开处理，阻塞/无积压不会自循环，历史不足仍显式恢复。

客户端位图先完整验证，再保留紧凑载荷与瓦片索引，呈现代时直接应用实际变化；新路径不维护细胞插入链表，旧协议兼容路径保留。50万高变化单包样本的队列保留数据约4.26MB→0.273MB。同机GPU单浏览器100代短测，展开→紧凑路径的解码中位约5.9→0.2ms、应用约17.9→14.9ms；均零漏收、零漏画、零恢复。流量仍约5.2MB/s/客户端（20Hz换算），没有宣称弱设备、公网或严格20Hz认证。

新客户端每500ms反馈收到/已绘制提交代号、队列长度/年龄和最近处理耗时。服务器校验会话与epoch，只用于诊断；悬停延迟数字可查看详情，控制台 `window.lifeWarNetwork` 可查看最近取样。旧服务器不声明能力时不发送反馈。

重启服务器、刷新客户端生效，无需新配置；重启会结束内存中的对局。详见[实施计划](docs/plans/2026-09-29-network-pipeline.md)与[结果报告](docs/performance/2026-09-29-network-pipeline.md)。
