# 结构化瓦片生产接入与本机验证（2026-10-01）

已将全同色块（SOLID）、按行展开游程（RLE）、变化掩码（MASK）接入生产 encoding 5。新客户端通过 `tileModes` 显式协商，依赖 `bitmapTiles` 和 `paletteTiles`；旧客户端继续原协议。每代独立编码、按序应用，历史缓存按能力隔离，实验 encoding 250 仍被生产解码器拒绝。

## 实现取舍

复用一次原调色板规划；变化掩码直接计算字节成本，全同色块复用存活数与阵营统计。游程最多尝试 32 段，前 32 格出现 8 次切换即放弃；也按当前最小载荷限制段数。保守筛选可能放弃部分节省，但不会改变棋盘或扩大包。整包仍与旧有序编码比较择小。解码先完整校验，再交给紧凑瓦片应用。

## 离线对照

固定 seed=91，演化预热 25 代、采样 20 代；21 场景 × 快照/增量 × 6 变体 × 20 = **5040 个完整包**，逐包完整棋盘重建与生产包不大于基线的断言全部通过。基线为已有局部调色板协议。字节包含 32B 协议头，不含 WebSocket/TLS；编码中位耗时来自同次 Node v24.11.1 本机采样。

| 场景 | 包 | 基线字节均值 | 生产字节均值 | 节省 | 编码中位 ms：基线 → 生产 |
| --- | --- | ---: | ---: | ---: | ---: |
| P03 | 增量 | 1895.3 | 1404.7 | 25.89% | 0.01 → 0.07 |
| P03 | 快照 | 112746.2 | 5735.0 | 94.91% | 6.37 → 4.21 |
| P04 | 增量 | 259980.4 | 259980.4 | 0.00% | 12.46 → 12.40 |
| P05 | 增量 | 139782.8 | 139782.8 | 0.00% | 11.88 → 12.19 |
| M12.5-C4-shuffled | 增量 | 16832.0 | 11712.0 | 30.42% | 0.35 → 0.48 |
| M25-C4-sorted | 增量 | 18928.0 | 14928.0 | 21.13% | 0.41 → 0.64 |

P03 为低变化扩张，P04 为高变化阵营混杂，P05 为四阵营空间交界；M 为合成中等变化密度，不代表实际游戏出现频率。原组合实验在 P04/P05 增量编码中位为 17.86/18.26ms；生产筛选消除了大部分重复规划开销。计时为短测，细小差异不应理解为稳定提速。

## 实际 WebSocket 与浏览器端到端

CPU sparse、主线程服务器、单个 Edge 154.0.4258.37 无头浏览器、DPR 1；每组预热 25 代后测量 100 代，每变体一轮。以下流量为测试工具记录的含状态 JSON 的每代 WebSocket 传输字节，不含 TLS、隧道和底层网络封装。

| 场景 | 每代字节：调色板 → 新模式 | 节省 | 实际代/秒：调色板 → 新模式 | 客户端应用中位 ms：调色板 → 新模式 |
| --- | ---: | ---: | ---: | ---: |
| P03 | 3383.44 → 2767.37 | 18.21% | 20.06 → 20.02 | 0.40 → 0.60 |
| P04 | 260950.07 → 260952.70 | -0.00% | 15.61 → 15.56 | 15.70 → 15.90 |
| P05 | 140932.57 → 140933.28 | -0.00% | 15.76 → 15.74 | 16.40 → 16.20 |

六组全部零漏收、零漏画、零失败、零恢复快照；每对预热和最终棋盘哈希相同。高变化仍约 15.6 代/秒，并未达到稳定 20Hz；主要瓶颈没有靠这次压缩消失。SOLID/RLE 展开整瓦片，低变化客户端应用成本略升。状态 JSON 与计时取样使高变化端到端字节存在数个字节的差异，离线棋盘包本身未增大。
