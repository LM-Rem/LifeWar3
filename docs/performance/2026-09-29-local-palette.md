# 压测基线与局部调色板（2026-09-29）

已完成本机基线与离线门槛验证，并接入显式协商的encoding 4。用户选择真实线路后续采集。本报告不声称公网、默认GPU＋worker部署或多设备20Hz认证。

## 方法与场景

Windows、i9-13900HX、Node v24.11.1、Edge 154.0.4258.37。确定性seed91，冻结production-20hz规则夹具，禁用卡牌发放，休眠延长、基地高耐久用于持续合成负载；不代表合法实战规则与普通对局分布。

- P04：约50万活格，奇数邻居B/S持续高变化，初始阵营逐格混杂。
- P03：80万单阵营起始，B1–8/S0–8持续低变化扩张。
- P05：与P04相同随机占据与演化规则，初始按x=500/y=500四象限分阵营，交界跨越32格瓦片；随后由实际引擎演化。

离线预热25代、连续20代；每代先记录全部1024瓦片的live、changes、colors、有效面积，再编码同一代增量/快照，按代交替A/B顺序。每个样本紧凑解码并应用到基准棋盘，逐字节比对权威棋盘。帧字节通过真实loopback TCP socket.bytesWritten统计，包含WebSocket帧头，关闭压缩，不包含TLS/隧道开销。计时仅编码/紧凑校验，不含应用与棋盘比较。

## 浏览器端到端本机基线

每组预热25代、连续100代，CPU sparse、主线程服务器、单个Edge无头客户端、DPR1、当前生产renderer与真实WebSocket。A/B串行；本工具直接注入确定性游戏状态，协商另由浏览器与socket集成测试验证。不是运行脚本默认GPU＋room worker性能测试。

| 场景 | 实际代/秒 原/新 | 每代字节 原/新 | 浏览器应用中位ms 原/新 |
| --- | ---: | ---: | ---: |
| P04 | 15.33 / 15.65 | 261,634.3 / 260,950.2 | 15.1 / 15.6 |
| P03 | 19.90 / 19.92 | 3,382.5 / 3,382.6 | 0.3 / 0.4 |
| P05 | 15.04 / 15.75 | 260,056.1 / 140,932.7 | 15.7 / 15.9 |

端到端流量含JSON、进度反馈响应与WebSocket帧头；不含客户端上行，不能等同于离线棋盘字节。P03的极小总字节差来自动态诊断JSON。每对起始/最终棋盘hash一致，六组均零漏收、漏画、恢复，队列峰值1。样本仅100代，不是长稳认证。P04/P05仍未通过既有严格实时门槛，浏览器应用耗时未显示提速。

本轮每500ms收集progress并测主连接ping：六组发送缓冲均0，computed−sent均0；高变化接收差主要1–2代，绘制差0，RTT受主线程长计算影响。结合单代计算超过50ms，证据更支持服务端计算限制，没有本地发送持续积压证据。进度字段异步采样，差值本身不证明丢包或线路问题。

## 诊断与后续线路采集

`network_status`增加bufferedBytes；正常app悬停延迟数字可查看，window.lifeWarNetwork仍为最近采样。新增network-capture工具记录网络状态、每秒累计WebSocket载荷字节、RTT、连接/快照数和可见性，不保存会话令牌、手牌或欢迎消息。快照数含初始快照及重连；采集结束后须按epoch/连接边界区分恢复。工具没有进度样本时以退出码2结束，避免把空报告当成功。

判断需联合观察：

- computed推进慢且服务端step/tick超时：演化/编码计算限制。
- computed−sent持续增大且bufferedBytes积累：发送路径拥塞；再用线路测速、客户端数量与实际字节速率判断带宽是否不足。
- sent−received持续增大：传输或浏览器消息处理延迟；单靠此差值不能区别二者。
- received−displayed、queueDepth/oldestMs及applyMs同时升高：客户端呈现跟不上。

真实线路至少记录两端设备、连接方式、可用上下行容量、玩家数、后台可见性和同场景包率。保持逐代和恢复限制；不得以丢代或放宽队列替代测量。

## 复现

```powershell
node tests/performance/palette-bandwidth.mjs
npm test
npm run test:browser:protocol -- --playwright <模块路径> --executable <浏览器路径>

node tests/performance/end-to-end.mjs --variant current-v2 --scenario P05 --bitmap --generations 100 --warmup 25 --clients 1 --rounds 1 --playwright <模块路径> --executable <浏览器路径> --output artifacts/performance/palette/e2e/P05-bitmap
node tests/performance/end-to-end.mjs --variant current-v2 --scenario P05 --bitmap --palette --generations 100 --warmup 25 --clients 1 --rounds 1 --playwright <模块路径> --executable <浏览器路径> --output artifacts/performance/palette/e2e/P05-palette

# 已有测试服务：本机可用--practice自动进入；真实线路用--headed手动加入测试房
node tests/performance/network-capture.mjs --url http://localhost:3000/ --practice --seconds 60 --playwright <模块路径> --executable <浏览器路径>
node tests/performance/network-capture.mjs --url https://HOST/ --headed --seconds 120 --playwright <模块路径> --executable <浏览器路径>
```

原始数据：`artifacts/performance/palette/report.json`（含逐瓦片样本、逐包耗时、hash与门槛），`e2e/*/report.json`（环境/源码hash、逐代计时、客户端进度原样本），`browser.json`，`capture-smoke.json`。artifacts按仓库惯例不纳入git。

覆盖单/双阵营非相邻owner、三/四阵营回退、边缘、删除、快照、同代修订、100代随机重建、展开/紧凑一致性、非法掩码/填充/长度与未协商拒绝。主线程四客户端混用与慢连接历史恢复、真实worker能力隔离、重连均有集成测试。浏览器比较包含主图像素、小地图和棋盘一致性，并验证v1、旧v2无4和新v2能力协商。

局部调色板仅在hello声明能力时自动请求；旧客户端保留旧字节与顺序。三/四阵营仍用原2bit，空瓦片仍用原位图。未增加变化掩码、状态JSON差量或新恢复策略。发布需重启服务器并刷新客户端；本轮没有重启用户现有服务。
