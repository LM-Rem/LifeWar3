# 逐代 GPU、渲染与网络优化结果

实施计划：[2026-09-25-gpu-smooth-network.md](../plans/2026-09-25-gpu-smooth-network.md)。本轮以用户本次要求为准：规则准确，不通过合并代数提速，小地图只需基本正确。

## 已实施

- **小地图**：复用世界像素纹理缩绘，约 10Hz 更新；去掉逐细胞 fillRect、贡献者索引和签名序列化。分区、基地与视口仍显示，颜色可混合，单个微小结构不保证旧版像素覆盖。
- **客户端存储**：`CellStore` 用 2 个百万长度 Uint32Array 保存双向链表，复用棋盘保存阵营。维持死亡、重生和覆盖后的插入顺序，避免几十万 Map 条目。代数、镜头 HUD 只在显示值变化时写 DOM。
- **逐代恢复**：房间共享最多 32 代 / 16MiB 历史；背压恢复逐包重发，所有代独立、有序。不合并最终状态。v2 保留瓦片编码，并在快照后的首代提供有序编码。历史不足、同代终局修订、客户端显式 resync 仍使用快照。
- **静态资源**：gzip、按内容计算 ETag、304、HEAD、按文件元数据失效；缓存不超过 32 文件 / 16MiB。图案库 JSON 1,882,037→108,251 字节，约减少 94.2%。
- **房间隔离**：异常记录房间码与错误，停止该房间，通知玩家退出重建；不继续可能只完成一部分的结算，其他房间继续演化。
- **GPU**：可选 `webgpu@0.6.1`（Dawn），原生 worker 执行 WGSL 单代邻居计数、B/S 和四阵营归属；保留 CPU 候选顺序及其后所有游戏结算。共享内存传输入/结果；主线程最多等待 100ms，然后同一代 CPU 回退。设备初始化失败也回退，局部法则期间走 CPU。

没有改变休眠规则、代数频率、胜负条件、部署规则或既有平衡配置。没有实行建议中的跨代合并，也没有通过降低发代频率伪装性能提升。

## GPU 正确性与生命周期

本机 Node 24.11.1、NVIDIA GeForce RTX 5070 Ti Laptop GPU、Blackwell、D3D12 驱动 32.0.15.9579。

- 512 组 B/S 掩码，每组连续 3 代（1,536 次），含边界、四阵营、优先继承与冲突，棋盘、活细胞顺序、变化顺序、v1 包与 CPU 相同。
- 完整生产棋盘回放 40 代、160 阶段比较，包含局部规则过期、同化过期、目标及休眠结算。
- 无 GPU、局部规则、关闭设备和强制超时回退；超时后迟到结果不会覆盖 CPU 棋盘，也不多推进一代。
- 测试发现直接 terminate 原生 Dawn worker 可导致进程无日志退出。改为等在途作业完成，再释放 buffer/device、关闭端口；不强制中断原生析构。失去响应的设备会被弃用并解除 worker 引用，可能保留资源到服务器退出。

## 单代密集基准

固定高密度输入，每次完整 step（目标、休眠、能量等）加 v1 打包。每档 2 次预热、10 次样本，CPU/GPU 交替顺序；结果逐次对照。这里不是连续自然演化，也不包含浏览器与网络。

| 初始细胞 | CPU 中位数 | GPU 中位数 | 降幅 | GPU 最慢样本 |
|---|---:|---:|---:|---:|
| 500,000 | 59.24ms | 50.56ms | 14.7% | 56.64ms |
| 800,000 | 58.55ms | 47.45ms | 19.0% | 54.01ms |
| 1,000,000 | 70.44ms | 55.29ms | 21.5% | 67.62ms |

复现：`npm run benchmark:gpu`。原始记录：`artifacts/performance/gpu/benchmark.json`（生成产物不纳入 Git）。

## 连续高变化全链路

生产服务器 tick、WebSocket、真实 Battlefield RAF；P04 合成规则，稳定约 50 万活细胞且每代约 50 万变化，单机单个 headless 浏览器、DPR 1、20 代 CPU 预热。不包含完整 HUD 开销、真实 LAN、公网链路或物理显示扫描；实际游戏页面另外通过 smoke 测试。

| 后端 / 协议 | 测量代数 | 实际代/秒 | tick 中位数 | 每代应用层流量 | 漏收/漏画/恢复快照 |
|---|---:|---:|---:|---:|---|
| CPU / v1 默认 | 60 | 17.57 | 52.26ms | 2,000,376B | 0 / 0 / 0 |
| CPU / v2 | 60 | 16.00 | 59.32ms | 1,500,572B | 0 / 0 / 0 |
| GPU / v2 | 60 | 18.04 | 51.43ms | 1,500,573B | 0 / 0 / 0 |
| GPU / v1 | 100 | 19.88 | 43.24ms | 2,000,522B | 0 / 0 / 0 |

最终 GPU/v1 队列峰值 1；帧工作 p95 12.2ms、p99 14.9ms，RAF 间隔 p99 16.8ms。有 2 次 tick 超过 50ms，且沿用的旧严格验收门槛未通过，不能宣称所有负载稳定 20Hz。v2 数据减少约 25%，编码成本也真实存在，因此 CPU auto、v1 仍是默认；GPU/v2 可按部署需求分别启用。

WebSocket permessage-deflate 的两个密集实验均积压：默认小输出块仅发出首个大包；扩大至 4MiB 后仍缺代并触发 4 次快照。其开关 `LIFEWAR_COMPRESSION=1` 仅供带宽受限、较轻负载试用，**默认关闭**。这与始终启用的静态文件 gzip 无关。

历史重放对短时背压减少全量快照，但不会创造网络容量：默认 v1 的上述极端负载仍需约 40MB/s 单客户端。超过历史窗口或长期传输不足仍会快照恢复，后续应考虑房间线程隔离与更低 CPU 成本的紧凑编码。

全链路原始输出为 `artifacts/performance/overview/e2e-default`、`e2e-v2`、`e2e-gpu-v2`、`e2e-gpu-v1`。流量为应用层数据加帧头估计；压缩实验中的该数字不是实际压缩 socket 流量。

```powershell
node tests/performance/end-to-end.mjs --gpu --variant current-v1 --scenario P04 --clients 1 --generations 100 --warmup 20 --output artifacts/performance/overview/reproduce --playwright <已安装Playwright路径>
```

## 验证与边界

- 最终全量 Node 回归 **156 通过、0 失败、0 跳过**（`LIFEWAR_TEST_GPU=1`，约 22.4 秒）；包含原规则、卡牌、休眠、多人、v1/v2、回放、类型数组存储、逐代重放、终局慢连接、压缩协商、gzip/ETag、房间隔离。普通 `npm test` 会跳过 3 项需要硬件 GPU 的测试。
- `npm run test:replay`：5 种种子 × 200 代、共 4,000 个阶段比较通过。
- 浏览器逐代呈现与部署预览回归通过，真实游戏 smoke 无异常且主地图像素一致。
- 旧小地图像素等价脚本属于历史验收；本轮入口是 `benchmark:overview`。GPU 是同步有界桥接，尚未把房间结算或 I/O 分离到 worker；小负载 GPU 未保证优于 sparse，多房间与手机长局未认证。

运行与回退命令见 README。本轮没有自动提交，也没有修改用户实战配置。
