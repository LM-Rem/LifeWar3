### T05：顺序与生命周期

网络差分用容量为棋盘面积的键缓冲、owner 数组和代际戳实现：首次触及决定包内顺序，最后一次写入决定值，死亡的 0 不会被丢弃。`clear()` 通常为 O(1)，32 位戳回绕时清空戳数组。打包直接读取有效长度，不再创建 Map 条目数组；每次返回独立 ArrayBuffer，慢消费者或 transfer 不会影响后续包。

阶段变更通过 `recordChange(key, oldOwner, newOwner, phase)` 同步发布，与最终网络差分分离。覆盖 deploy、seed、evolution、core、eliminate、purge、dormancy；可选 `onCellTransition` 消费完整中间状态，生产默认不分配逐格事件对象。活细胞使用两个 Uint32 缓冲交换，删除只做稳定压缩，保留候选、AI、快照顺序。数组专属测试已改用迭代视图；夹具直接写棋盘后调用 `rebuildDerivedState()`，游戏命令不绕过统一入口。

固定存储成本：alive 双缓冲 8,000,000 字节，网络差分 9,000,000 字节，共约 16.21 MiB/房间，取代原来的动态数组与 Map，而非净增加该数值。稀疏房间的常驻内存更高；密集房间避免大规模数组、Map 条目与 GC 压力。完整进程内存采样见 JSON，不将一次 heapUsed 采样视为内存峰值。

### T06：历史时序保持不变

`current1/current2/currentCount` 记录下一次扫描应看到的棋盘，额外 4,000 字节；原 `hash1/hash2/count` 仍表示最近扫描时的值。每代仍更新年龄、周期、预警、8 代指纹历史和 9 张完整棋盘。休眠删除发生在快照写入之后，只调整当前指纹，不回写历史。

仍保留 50 格瓦片、2 格哈希观察重叠、10 格精确 halo、原有哈希和精确比较。当演化变化数超过 `max(256, nextAlive.length / 4)` 时，auto 模式在处理该批变更之前选择完整重建，避免先为整批逐格维护再重扫。部署/道具失效仍重置原有相邻区域年龄；免疫与效果到期逻辑不变。

可通过 `LIFEWAR_DORMANCY=legacy` 在新游戏中使用每代全量指纹扫描，或 `incremental` 强制增量；默认 `auto`。该开关不改变游戏平衡配置。运行中不要直接切换 mode：如需要调试切换，必须设置 `dirty=true` 后在下一次扫描重建当前指纹，保留历史与年龄。

### T10：批量上传

世界离屏画布保留原尺寸、颜色、drawImage、最近邻采样和图层顺序。RGBA 常驻内存增加 4,000,000 字节；死亡置为全透明。每个网络包应用完成后上传所有脏区域，不延迟到下一包、不合并代。脏瓦片超过总数的 1/4 时全图 putImageData；快照、重连和 reset 清空旧数据。网络包、世代提交和 RAF 调度不变。

### T11：保留原叠色

继续按“背景/网格 → 领地 → 节点 → Map 插入顺序细胞 → 基地 → 相机框”绘制。细胞仍是原有小地图坐标下的半透明 1×1 矩形，不按阵营分组、不缩放主棋盘代替。

缓存最终不透明合成，16×16 像素瓦片使用扩展边界收集贡献者，整数裁剪内按原插入顺序重画；owner 更新不重排，删除重生重新追加。背景归属、基地状态、视角所属阵营、尺寸、reset、快照均失效。相机框继续每次原 30Hz 调度绘制。

贡献索引在第一次小范围增量前按需建立；超过 4096 条的包不维护索引，直接走全图绘制，脏瓦片超过一半也全图重画。稳定高密度场景可直接命中缓存，但首次建立大索引、全图分散变化仍有明显开销。节点或领地变化目前保守地重建完整底图，而不是只标记其局部区域；因此不会遗漏间接的领地归属影响。

## 正确性证据

- `npm test`：108 项通过。原有协议、多人、AI、卡牌、清理、顺序回放测试全部通过。
- 新增随机差分 160,000 次写入与 Map 精确对照，包含反复覆盖、清空、戳回绕；独立包与转移后继续封包测试通过。
- 1000×1000 棋盘随机变更 10,000 代：每代比较两个哈希、计数、年龄、周期、全部 8 代指纹历史及全部 9 张棋盘；含所有权变化、扫描后删除、定期强制全量重建。该测试隔离休眠检测，不把它描述成 10,000 代完整游戏演化。
- 原有完整游戏逐阶段回放覆盖 5 个种子各 200 代及部署、净化、伤害、淘汰、发牌与到期等情境；board、alive、changes、状态、RNG 与包字节一致。
- 强制构造“指纹候选但 halo 内容不同”的情形，精确校验拒绝删除。
- Chrome 153.0.8010.53：188 项无损 PNG 比较通过，主画面和小地图均与冻结渲染器一致。覆盖 D=0/1/1000/100000/500000、四阵营、缩放 0.45/1/3.5/7/22、DPR 1/2、分数相机、边界、owner 更新、删除重生、全图分散增量、归属变化、尺寸变化、reset/重连。
- 比较使用 toDataURL 无损输出，避免反复 getImageData 使 Chrome 自动切换 Canvas 后端，造成基线和缓存采样路径不同。证据限于该浏览器测试环境；尚非跨设备/跨浏览器认证。

## 性能结果

服务端正式结果与源码哈希见 [机器可读汇总](t05-t11-summary.json)。每场景每版本 5 个独立进程，各预热 30 代、测量 100 代，T04/current 交错运行。使用冻结 20Hz 配置，测量 step+packet；不含网络、浏览器、多房间。三个场景均为固定时间、高 HP、高休眠阈值的合成持续负载，不把非法长期法则当作正常卡牌时长。

| 场景 | 平均 ms：T04 → 当前 | p95 ms：T04 → 当前 | 平均耗时下降 | 超过 50ms：T04 → 当前 /500 |
|---|---:|---:|---:|---:|
| P01 | 2.074 → 1.579 | 2.485 → 1.767 | 23.9% | 0 → 0 |
| P03 | 55.271 → 30.457 | 62.061 → 32.443 | 44.9% | 412 → 0 |
| P04 | 88.272 → 63.590 | 94.420 → 65.585 | 28.0% | 500 → 500 |

P01 为 24,000 静物；P03 测量期约 82–92 万细胞扩张、每代约 1,700 变化；P04 约 50 万细胞且每代约 50 万变化。P03 的本次服务端单房间样本进入 50ms 预算，P04 仍不达标。p99、max、逐轮均值、L/D、内存、环境及源码哈希均保留在汇总 JSON。

额外消融检查：保留 T05 有序缓冲，将休眠设为 legacy，单进程预热 30 代并测量 100 代，P01/P03/P04 平均分别为 2.194/49.620/63.953ms。该单轮检查不是正式五轮对照，但支持“低 D、大 L 场景主要受益于增量休眠，高 D 自动重建避免额外增量成本”的解释。T05 单独在稀疏场景不保证收益，默认启用的是经过组合验证的 T05+T06。

浏览器测量为单次 headless 会话内的探索性时序，受 Canvas 异步栅格化、计时精度与 GC 影响，不与服务端基准并行运行；不是 RAF 或物理呈现帧率认证。

下表取 DPR 1，单位 ms；每次快照测一次，稳定小地图取连续 20 次平均。小于计时分辨率的结果只记“<0.1”，不解释为零成本。

| 负载/操作 | 冻结渲染器 | 当前 |
|---|---:|---:|
| 10 万细胞快照解码+纹理更新 | 21.1 | 6.6 |
| 50 万细胞快照解码+纹理更新 | 254.1 | 23.1 |
| 50 万细胞首次小地图 | 238.7 | 241.7 |
| 50 万细胞无变化小地图平均 | 247.08 | <0.1 |
| 50 万细胞上局部修改，首次建立索引并画小地图 | 见 JSON | 56.7 |
| 后续局部修改并画小地图 | 见 JSON | 6.2 |
| 50 万细胞上每包改动 10 万，解码+小地图，8 次平均 | 300.26 | 242.64 |
| 每包改动 50 万，解码+小地图，8 次平均 | 498.89 | 281.09 |

稀疏快照有常驻像素缓冲清空/上传成本：空快照约 0.3 → 2.4ms，1,000 条约 0.3 → 0.7ms。缓存的收益主要来自大批量纹理更新、重复小地图绘制和局部变化，不能声称每次调用都更快。分散在全图的 1,000 个变更触发全图重绘，DPR 1 约 240.74 → 235.95ms，DPR 2 约 238.44 → 250.50ms，基本无收益且可能有小幅退化；完整原始两组时序保留在 JSON。密集小地图仍远超 33ms 的调度预算。

## 复现

```powershell
npm test
npm run test:browser:smoke -- --playwright <已安装的playwright目录> --executable <Chrome路径>
npm run test:browser:equivalence -- --playwright <已安装的playwright目录> --executable <Chrome路径>
node tests/performance/freeze-stage.mjs 6a5d967b69fee11d7d70a5d955b99326e071e80e artifacts/performance/t04-repro
node tests/performance/runner.mjs --backend baseline --baseline artifacts/performance/t04-repro/ --scenario P03 --warmup 30 --generations 100 --rounds 1 --output artifacts/performance/repro-before
node tests/performance/runner.mjs --backend current --scenario P03 --warmup 30 --generations 100 --rounds 1 --output artifacts/performance/repro-after
```

每场景交替运行以上两个 runner 5 次，输出目录分别使用 `artifacts/performance/t05-t06-final/<P01|P03|P04>/<1..5>/<baseline|current>`，可再执行 `node tests/performance/summarize-stage.mjs` 汇总。完整原始采样位于 artifacts，不纳入 Git；精简汇总已保存到 docs。复现脚本不安装依赖或下载浏览器。

## 范围与回退

这四项已完成实施与本地阶段验证；多房间容量、长时间真人对战、低端机、手机、网络背压及逐代呈现队列仍属于后续任务。尤其 P04 和密集小地图全量重画仍超预算。没有添加跳帧、降低画质、降低逻辑频率或改变规则；也没有将现有“多个包可能在一次 RAF 前应用”的问题描述成已经解决，该保证属于 T12。

休眠可用 legacy 模式回退。其余改动应按模块成组回退：引擎与有序容器一起恢复，renderer 与两个缓存模块一起恢复；不能仅删除导入目标。当前没有自动提交、部署或修改对战平衡配置。
