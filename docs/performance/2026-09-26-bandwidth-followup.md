# 窄带网络续优化结果

按用户约束保留 GPU＋v2。建议输入为 `docs/优化建议02.md`，不是额外需求来源；逐条判断见实施计划。没有采用 GPU＋v1 默认或合并多代降级。

## 实现与收益

- v2 encoding 2：原始顺序的坐标差值 ZigZag＋LEB128，将阵营放入低3位；只在完整包更小时选用。显式能力协商，新旧v2可同房，历史重放也区分能力。快照、负差值、边界跳跃、出生顺序均保留。
- 预览比较实际依赖字段，仍检测能量、淘汰、节点等原地修改。避免序列化与预览无关的玩家字段。
- 领地查询达到缓存阈值后只构建访问行，避免同步计算百万格；完整索引显式接口保留。内存上限仍约2MB，并非节省索引内存。邻接缓存只存几何关系，归属仍实时判断，几何失效接口同时清理两类缓存。
- 清理小地图空钩子、废弃逐格回调与颜色常量。旧绘制仅留在历史基准适配器中。
- 常规 benchmark 增加持续50万高变化档；修正旧浏览器测试对近似小地图的过时精确要求，主图与细胞顺序仍严格对照。

## 测量

环境：本机 Node 24.11.1，Chromium 151，RTX 5070 Ti Laptop / D3D12。以下均为单机短测，不代表穿透服务实测或多房间长稳认证。P04 使用固定奇数邻居规则和禁用休眠构造持续50万高变化；P03为80万以上低变化扩张，P01为2.4万静物。

`node tests/performance/bandwidth.mjs`：CPU预热25代，采样20个连续代，各代交替测原v2与新扩展，增量和快照分别验证重建棋盘完全一致。字节来自真实 socket.bytesWritten 差值，含WebSocket帧头，关闭deflate，不含TLS及隧道封装。

全链路的wireBytes为应用消息加帧头计数，与上面的实际socket测量分开；原始结果分别在 `artifacts/performance/bandwidth/e2e-legacy/report.json` 和 `e2e-varint/report.json`。收益是少45.7%的每代流量，代价是计算及解码变慢。没有宣称稳定20Hz。仅单种种子和短窗口，不能据此声称所有负载收益相同。

20Hz的该极端场景仍约需16MB/s/客户端；有限历史不能解决永久带宽不足，超过窗口仍恢复快照。新编码可以让同一16MiB历史存更多代，但仍受32代上限限制。不默认启用有积压记录的WebSocket压缩。

## 验证

- 158项测试含GPU硬件验证通过；协议随机1000代包含扩展选择，混合v1/旧v2/新v2的真实WebSocket慢连接逐代恢复与顺序比对通过。
- 5种种子×200代×4结算阶段＝4000次回放对照通过。
- 主棋盘DPR1/2共156项PNG像素对照通过。
- 协议浏览器：参考主图和有序存储比对；当前v1/v2小地图互相一致；真实新旧服务端协商、刷新重连通过。近似小地图不再与历史逐细胞覆盖像素强行相等。
- 小地图四象限阵营颜色、尺寸变化、玩家状态刷新、清空与重连恢复通过；部署预览7种变化与未缓存结果一致。
- 常规benchmark新增档完成预热20代＋100代；活细胞约49.9万，变化约50万。它测CPU默认路径与v1打包，不冒充GPU＋新v2全链路数据。

## 建议处理边界

房间错误隔离、逐代历史、静态gzip、HUD脏检查继续保留。索引下发没有采用，以免增加带宽；改用本地按行缓存。没有盲改next.fill或休眠历史，它们涉及交换缓冲残留及周期精确判断；窄化marks/tile和房间worker需要独立基准及边界设计。app拆分、库搜索索引暂缓。

图案写接口仍无鉴权且存在读改写竞态，未修复；GPU永久挂起时仍可能保留原生资源到进程退出，未声称已解决。独立管理权限流程与房间worker是后续有价值的工作。完整判断见 `docs/plans/2026-09-26-bandwidth-followup.md`。
