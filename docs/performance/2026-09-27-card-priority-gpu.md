# 选卡优先与 GPU 局部法则实施结果

## 发现与实现

原卡牌 UI 使用呈现后的棋盘状态；选卡回执与棋盘包共用 TCP/WebSocket，已经进入发送队列的大包无法由后来的选卡消息插队。新控制连接通过现有会话令牌绑定在线玩家，只转发选卡、出牌与 ping，沿用主连接的权限与限流。主连接断开、被新会话替代或主动退出时撤销控制连接。一个玩家仅保留一个控制连接，其他客户端的手牌与候选不发送给它。

服务端每秒约5次发送独立卡牌状态，以及操作后立即发送；控制状态带 roomEpoch 和单调序号，超过64KiB待发送缓冲时跳过该次可替换状态，防止无界排队。棋盘协议、代数和历史重放没有变化。客户端控制连接断开后1.5秒重试，期间新操作回退主连接；不会自动重放已经发出的命令。卡牌状态立即更新手牌和征召 UI，旧棋盘状态不能覆盖它。

点击候选立即显示选中与提交状态；请求携带征召轮次/代数，服务端拒绝过期轮次。未确认前禁止重复点击，8秒无确认允许手动重试，最终以服务器结果为准。旧客户端仍可走原协议。

GPU 新增2KiB局部法则缓冲，圆内后添加的规则优先，支持至多64个局部法则。非整数、负数或大于10000的圆形参数、数量超限时保留CPU回退；当前卡牌生成的参数均支持。只将细胞演化放在GPU，基地、节点、休眠与其他结算仍按原顺序执行。

## 测量

浏览器：Edge 154.0.4258.37，无头，1280×900，服务器CPU默认后端、v2。旧版前端固定为提交 `19f2e4a7b7b63895bb97868ef61b15efe445d83f`；新旧共用当前服务端。主连接发送消息人为延迟1200ms，模拟排队，控制通道正常。

| 前端 | 从调用浏览器点击到确认关闭弹窗 |
| --- | ---: |
| 旧版 | 1212.4ms |
| 独立控制通道 | 288.1ms |

包括 Playwright 点击等待和浏览器调度成本，不是纯网络RTT。验证点击事件内即出现提交提示与禁用状态、确认后仅一张手牌、释放旧消息不回滚、控制连接独立重连、无页面异常。不是限速代理、真实公网、多机或长稳认证。

GPU：NVIDIA RTX 5070 Ti Laptop，D3D12，两个重叠局部法则。串行CPU/GPU交替，2次预热＋10次采样；每次重新设置同一密集输入。包括完整单代结算与v1打包，未含v2编码和网络发送。

| 初始细胞 | CPU中位 | GPU中位 | GPU最慢采样 |

| 500000 | 59.14ms | 44.24ms | 60.42ms |

数据不构成稳定20Hz承诺，也不是GPU＋v2端到端数据。原始结果写在忽略的 `artifacts/performance/card-priority/results.json` 和 `artifacts/performance/gpu/benchmark-local.json`。

## 验证与复现

- 完整常规测试：160项中157通过、0失败、3项GPU默认跳过（这些GPU测试另行显式运行通过）。
- CPU冻结参考回放：5种种子×200代，4000次阶段比较通过。
- 显式硬件GPU测试：4项全通过，涵盖512种掩码、阵营、同化、地图边缘、1/2/64个局部法则和重叠优先级、65个局部法则回退、局部规则到期、休眠与设备超时。
- WebSocket回归覆盖背压期间选卡、候选/手牌隐私、错误令牌拒绝、控制权限限制、过期轮次、重复选择拒绝、主连接关闭撤销控制。
- 真实RAF逐代呈现测试：最终单独运行通过，队列峰值4、最长等待约195.9ms；旧版前端对照峰值5。此前两次新版运行在“队列峰值不超过5”的门槛失败（其中一次与完整测试并行，一次单独运行），失败前的逐代完整性、状态代数对齐和无恢复断言均通过。没有放宽验收阈值；时序波动仍存在，不能将最终单次通过当作稳定实时认证。为该脚本增加 `--baseline <git提交>` 和队列峰值诊断，便于继续复测。

```powershell
npm test
npm run test:replay
$env:LIFEWAR_TEST_GPU='1'
node --import ./tests/setup.js --test tests/gpu-evolution.test.js
Remove-Item Env:LIFEWAR_TEST_GPU
npm run benchmark:gpu -- --local
node tests/browser/card-priority.mjs --playwright <Playwright模块路径> --executable <浏览器路径>
```

## 下一阶段

完整房间worker隔离尚未实现。当前GPU仍用Atomics.wait同步等待，CPU结算、编码和浏览器解码绘制长任务仍可能延迟交互；独立TCP连接也共享物理带宽。本阶段优先消除卡牌对棋盘发送/呈现队列的依赖，不能宣称已消除所有卡顿。下一阶段应单独迁移房间计算与命令边界，并测量CPU密集下的输入延迟，再处理浏览器解码长任务；继续保留逐代一致性验证。
