# 房间线程隔离实施结果

## 已实现

运行脚本默认启用 `LIFEWAR_ROOM_WORKERS=1`。每个对局独占一个Node房间worker，内部拥有Game、AI、计时、GPU桥接、规则结算、协议编码基准和历史。主线程只保留大厅成员、连接与状态摘要，执行小消息转发和WebSocket发送；不再持有或修改worker房间的棋盘，也不调用其Game.step/packet。

GPU上传与回读在GPU计算线程内，等待结果与CPU结算在房间线程内。未安装GPU依赖或设备失效时，在房间线程内回退CPU，不把工作搬回主线程。每房间独立GPU实例会增加线程、驱动与内存成本；仍受最多6房间限制。

部署、选牌、出牌、重连和离线命令按消息端口FIFO顺序，在完整一代之间执行。连接会话序号与对局epoch阻止旧输出投递到新连接/新对局。卡牌回执沿用独立控制通道，不等待棋盘批次确认。

每房间最多128条未完成操作；超过限制明确拒绝，不自动重放结果未知的命令。启动超时20秒、运行中无响应10秒会报告房间故障并停止接收其操作。异常不自动接管可能半结算的状态，其他房间继续工作。

线程间最多一个未确认棋盘批次。主线程发送后回报实际socket缓冲量；慢连接在worker内从32代/16MiB历史逐代重放，历史不足明确发送快照，不合并代数。历史中的ArrayBuffer保留，输出复制一次后transfer，同批次相同包共享；每个客户端按约256KiB的批次预算重放，单个大包仍原样发送。快照后首个v2增量保留有序编码，以保持客户端插入顺序。

重赛、房间销毁、无人90秒过期和关服均关闭worker；普通断线保留90秒恢复窗口并继续演化。结束的房间保留worker供重连/重赛，随后按上述生命周期清理。GPU正常关闭已实测；原生驱动永久挂起仍采用有界等待和unref，不强制终止Dawn线程，不能宣称彻底解决驱动级资源挂起。

## 选卡调度修正

最初隔离版在高负载下发布候选后立即开始下一代，响应候选的选卡请求可能多等一整代。一次修正前短测中，同房间选卡P95约67ms。

最终仅在“在线真人仍有待选牌，且下一代已超期”时留2ms命令处理窗口；没有待选牌、仅机器人待选或下一代尚未到期时保持原调度。操作仍在代际边界执行，不能打断正在运行的一代。操作系统定时器可能让实际窗口长于2ms，因此必须同时观察吞吐代价。

## 本机测量

RTX 5070 Ti Laptop / D3D12，Node 24.11.1，本地WebSocket；配置20Hz、GPU＋v2差值编码、无WebSocket压缩。一个约50万细胞的持续高变化合成房间（非标准B/S规则、关闭AI、延长休眠），另一个轻载探测房间或直接在高负载房间选牌。探测客户端在独立线程计时，避免服务器主线程阻塞使客户端计时器也停住。每种执行方式30次选卡，使用重复征召夹具，不是正常发牌节奏。

| 选择所在房间 | 执行方式 | 选卡中位 | 选卡P95 | 选卡P99/最慢 | 主连接ping P95 | 高负载房间观测Hz |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 另一轻载房间 | 原主线程执行 | 52.62ms | 58.78ms | 60.40ms | 58.50ms | 18.09 |
| 另一轻载房间 | 房间worker | 0.44ms | 0.60ms | 3.32ms | 0.49ms | 18.89 |
| 高负载房间自身 | 原主线程执行 | 0.85ms | 1.26ms | 50.91ms | 49.87ms | 19.18 |
| 高负载房间自身 | 房间worker＋待选窗口 | 0.78ms | 4.13ms | 4.51ms | 0.60ms | 16.16 |

主线程event-loop P99：跨房间测试约85.98→20.99ms，同房间测试约70.39→21.00ms；使用Node的10ms分辨率采样，受Windows定时器粒度影响。

P99在30个样本中等同最慢值，不代表可靠的长期尾延迟估计。样本在收到新候选后立即提交，原主线程路径有时恰好赶上计算间隙，因此同房间原版中位/P95很低。最终版同房间P95没有改善，最慢样本改善；持续征召夹具的吞吐从19.18降至16.16Hz，是为选卡预留窗口的明确代价。实际游戏仅在征召待选时有该额外窗口，不能把这个频率损失套用于整场，也不能把本地亚毫秒RTT套用于公网。

这是连接与服务器确认测量，不含浏览器输入、渲染、TLS、Ngrok和真实弱网；不证明高变化场景稳定20Hz，也不构成六房间长稳认证。raw数据位于忽略的 `artifacts/performance/room-workers/gpu-other.json` 与 `gpu-busy.json`。

## 验证

- 定向测试覆盖v1/v2/差值编码、185代runtime参考/密集回放、客户端插入顺序、快照后首代、有界输出与历史、会话隔离、隐私、重复选择与90秒离线判负。
- 真实worker WebSocket覆盖部署、选卡、出牌、慢连接逐代补发、重连、投降、重赛和资源关闭。人为阻塞一个worker 700ms时，另一房间选卡与主线程ping在500ms门槛内完成；故障只停止所属房间。
- 桥接测试覆盖128条在途上限、启动超时、运行无响应与关闭。
- GPU＋v2＋worker真实浏览器低负载逐代测试通过：122代前缀完整，队列峰值3，最长等待约114.7ms，状态与呈现代数对齐，包含突发消息与可见性恢复。
- 完整测试、显式硬件GPU与冻结参考回放结果见本文件末尾最终验收记录。

## 复现与回退

```powershell
npm test
npm run test:replay
$env:LIFEWAR_TEST_GPU='1'
node --import ./tests/setup.js --test tests/gpu-evolution.test.js tests/room-workers.test.js
Remove-Item Env:LIFEWAR_TEST_GPU
npm run benchmark:rooms -- --evolution gpu --target other --samples 30
npm run benchmark:rooms -- --evolution gpu --target busy --samples 30
```

浏览器测试可设置 `LIFEWAR_ROOM_WORKERS=1`、`LIFEWAR_EVOLUTION=gpu`、`LIFEWAR_BOARD_PROTOCOL=2` 后运行 `tests/browser/live-presentation.mjs`，通过 `--playwright` 和 `--executable` 指定本机模块与浏览器路径。

```powershell
# 仅回退房间执行方式，GPU＋v2仍由运行脚本默认启用
$env:LIFEWAR_ROOM_WORKERS='0'
npm start
# 恢复隔离默认值：退出服务器后
Remove-Item Env:LIFEWAR_ROOM_WORKERS
npm start
```

重启结束内存中的现有对局。直接导入createServer不会自动加载运行脚本默认值；使用 `createServer({roomWorkers:true})` 或相应环境变量。原inline路径保留用于回退和历史基准。
