# 自适应位图实施与验证（2026-09-28）

## 结果与边界

已实现 v2 encoding 3、bitmapTiles 显式协商、稀疏/位图自适应和房间线程传输。仅放宽新能力客户端集合插入顺序；没有改变服务器 OrderedCells、AI、演化或结算顺序，也没有降频、合并代数、启用通用压缩或客户端演化。

新能力客户端仍可收到 ordered24 或差值包（更小时），但不保证跨包的集合遍历顺序。当前主图按坐标纹理绘制，小地图缩绘该纹理；保留 CellStore 兼容接口，未引入第二套渲染器。

## 编码与网络载荷

命令：`node tests/performance/bitmap-bandwidth.mjs`。同进程每场景预热25代，再连续采样20代；每代交替测差值扩展和位图扩展，重建棋盘逐格对照。表内为中位数；真实 loopback TCP socket.bytesWritten 差值，包含WebSocket帧头，未开启deflate，不含TLS/隧道。原始数据：`artifacts/performance/bitmap/report.json`。

| 场景 | 差值 TCP字节 | 位图 TCP字节 | 编码ms（差值→位图） | 解码ms（差值→位图） |
| --- | ---: | ---: | ---: | ---: |
| P01 静物增量 | 34 | 34 | 0.0022→0.0018 | 0.0014→0.0009 |
| P01 2.4万静物快照 | 36,092 | 36,092 | 0.104→0.160 | 0.457→0.473 |
| P03 83万低变化增量 | 1,904 | 1,904 | 0.034→0.021 | 0.071→0.061 |
| P03 83万快照 | 865,512 | 320,236 | 4.677→6.450 | 10.083→3.364 |
| P04 50万高变化增量 | 806,336 | 260,537 | 10.694→8.691 | 9.541→6.523 |
| P04 50万快照 | 806,325 | 260,523 | 7.522→8.761 | 9.475→6.368 |

高变化增量减少67.7%；20Hz换算约16.13→5.21MB/s/客户端（十进制MB）。位图比理想全图250KB多出瓦片头、边缘填充及局部稀疏数据。低变化包没有增大，但候选估算不是免费的：例如静物快照编码稍慢，密集快照编码也增加成本。

P04是固定奇数邻居规则、禁用休眠的持续高变化合成负载，不能视为普通B3/S23对局的平均流量。该测量没有覆盖所有种子或长期公网情况。

## GPU与真实浏览器逐代对照

RTX 5070 Ti Laptop / D3D12，Edge 154.0.4258.37，单浏览器、DPR1；相同25代预热＋60代测量，先位图再差值，两次独立运行。使用既有主线程生产循环基准（非房间worker吞吐基准），真实GPU、WebSocket、Battlefield RAF。初始/最终棋盘hash完全一致。

| 每代含JSON和帧头字节 | 815,246 | 261,591 |
| 实际代/秒 | 17.38 | 19.09 |
| 单代含编码发送中位ms | 55.30 | 49.92 |
| 浏览器解码中位ms | 8.10 | 6.90 |

| 漏收 / 漏画 / 快照恢复 | 0 / 0 / 0 | 0 / 0 / 0 |
| 队列峰值 | 1 | 1 |

位图表示整块状态，解码后可能遍历近百万格；虽然渲染器跳过未变化格，应用开销仍增加。这个代价不能用服务端吞吐改善掩盖。两组均未通过基准的严格实时门槛；只说明本机短测没有积压或丢代，不承诺稳定20Hz、弱客户端或公网表现。

复现（PowerShell；将两个路径替换为本机安装路径）：

```powershell
$bitmapBenchArgs = @('--variant','current-v2','--scenario','P04','--gpu','--generations','60','--warmup','25','--clients','1','--rounds','1','--playwright','<Playwright模块路径>','--executable','<浏览器路径>')
node tests/performance/end-to-end.mjs @bitmapBenchArgs --bitmap --output artifacts/performance/bitmap/e2e-bitmap
node tests/performance/end-to-end.mjs @bitmapBenchArgs --output artifacts/performance/bitmap/e2e-varint
```

`--bitmap` 显式选择新编码；该基准不经应用握手，不应将未加参数的current-v2当作新客户端默认协议。原始报告位于上述两个目录的report.json。wireBytes是应用消息＋帧头统计，独立于前面的实际socket计数。

## 正确性与兼容验证

- 全套 `npm test`：182项，178通过、0失败、4项硬件GPU测试默认跳过。随后补充位图长历史恢复用例，`tests/room-runtime.test.js` 的8项全部通过。
- 新编码覆盖200代随机混合更新、快照、边缘瓦片、删除、新生、同代修订、不可变服务器keys、小包回退，以及重复瓦片/格子、非法模式、数量、长度、存活/阵营填充和未协商包拒绝。
- 既有1000代v1/v2棋盘与插入顺序对照仍通过；新能力按棋盘内容比较，不要求集合顺序。
- 四客户端真实WebSocket混合协议、慢连接逐代重放通过；长积压走显式快照恢复。房间运行时同时对照服务器棋盘、alive顺序和完整结算状态。
- 实际独立房间worker以50万高变化数据同时向差值和位图客户端发送，各代棋盘一致；位图能力重连后快照和后继增量通过，也覆盖仅位图、不启用差值的能力组合。
- Edge无头浏览器DPR1/2：48项主图像素对照、32项当前协议小地图对照、旧协议32项集合顺序对照通过；新编码额外验证棋盘hash。新/旧服务器协商及刷新重连通过。原始报告：`artifacts/performance/bitmap/browser.json`。
- 浏览器基准验证的是Canvas输出与绘制提交，不代表物理显示器呈现或真实网络认证。

## 启用与维护

重启服务器、刷新客户端自动协商；旧客户端继续原协议，历史缓存按能力隔离。更新不重启正在运行的用户对局。原有32代/16MiB历史、64MiB解码队列和500ms恢复限制保持不变；减少传输字节并不意味着解码队列内存也等比例减少。混合旧客户端会继续占用对应协议的编码CPU与历史空间。

后续若需要进一步降低客户端开销，应单独评估直接应用位图的路径；若要求低于约5MB/s的持续极端负载，还需另行评估视野同步或本地演化。
