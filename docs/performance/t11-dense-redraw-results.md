# T11 密集小地图重绘续优化

2026-09-24。直接对照基线为 T07/T08/T12 完成提交 `0dad0ec3fb0a6388951aadd033ce6a1c326c1e4e`。本轮仅修改小地图缓存与颜色设置，不涉及服务端演化、CUDA 或协议。

## 实施结果

- 四种半透明细胞颜色在模块加载时生成，避免每次全量重绘逐格转换透明度、拼接字符串。
- 连续同色细胞只设置一次 fillStyle。细胞本身仍逐个 fillRect，保持 Map 插入顺序与原始坐标。局部瓦片之间绘制基地会改变 fillStyle，因此基地绘制后显式清空颜色命中状态。
- 将细胞合成失效与背景失效分开。密集包、快照失效合成及贡献索引，复用背景与 Canvas 存储；归属、基地状态、所属阵营、领地引用与尺寸仍参与背景失效检查。仅尺寸改变时重设 Canvas 宽高。
- 完整重绘挂起期间，后续小包不建立或修改贡献索引，重绘时直接读取最终有序细胞集合。下一次局部更新再按需建立索引。

没有合并世代、调整小地图调度频率、减少细胞绘制、改变透明度或改变 Canvas 后端。全量重绘复杂度仍为 O(L)，本轮降低常数及无效缓存重建成本。

## 五轮性能对照

每种版本每轮使用独立 Chrome 进程，前后交错顺序，5 轮；每场景预热 2 次，采样 10 次，共 50 次。小地图 180×180、DPR 1；细胞键按固定排列分散至整张棋盘。四阵营负载按插入顺序交替 owner，单色负载整批切换 owner。包预先构造，不将夹具构造时间算入测量。

“小地图提交”仅是 drawMinimap 调用返回耗时；“更新至完成”包含 updatePacket、drawMinimap、强制完成绘制的 PNG 编码。后者含编码和读回成本，不能解释为物理显示延迟；但能防止仅把绘制推迟到异步任务而造成虚假提速。没有在性能测量期间并行运行其他项目测试。

| 活细胞 / 每包变更 / 颜色 | 小地图提交均值 ms：原 → 新 | 更新至完成均值 ms：原 → 新 | 完成耗时下降 | 完成耗时 P95 ms：原 → 新 |
|---|---:|---:|---:|---:|
| 10万 / 10万 / 四阵营 | 20.29 → 14.69 | 61.52 → 55.00 | 10.6% | 70.1 → 60.8 |
| 50万 / 10万 / 四阵营 | 204.44 → 175.40 | 259.00 → 232.78 | 10.1% | 291.2 → 257.3 |
| 50万 / 50万 / 四阵营 | 209.96 → 179.73 | 290.09 → 255.55 | 11.9% | 320.9 → 279.2 |
| 50万 / 50万 / 单色 | 201.05 → 160.29 | 294.39 → 248.96 | 15.4% | 327.3 → 271.0 |

稳定无变化场景仍命中缓存，批量计时的单次均值低于 0.01ms；不将其解释为零成本。四阵营 50 万变化的小地图提交均值下降约 14.4%，单色下降约 20.3%。编码完成后的收益更小，以上最终判断使用更保守的完成口径。

**50 万细胞密集重绘仍明显超过 33ms 预算，未通过密集实时性能门槛。** 这些是合成浏览器负载，没有复测服务端性能、多房间容量或物理呈现帧率。完整环境、源码 SHA256、各指标 P95/P99/max 在 [机器可读汇总](t11-dense-redraw-summary.json)，原始逐轮采样在 `artifacts/performance/t11-dense/benchmark/report.json`。

## 未采用的实验

单次探索中，willReadFrequently 软件 Canvas 和 Path2D 合并矩形更快，但 PNG 与原始 fillRect 不同，因此拒绝。预绘制色块的 drawImage 路径更慢。按像素覆盖依赖重排互不相交矩形，额外建表及栅格化成本抵消收益，也未采用。实验仅用于筛选，不作为正式性能结论。

后续若继续压缩密集重绘，应评估保序批量绘制，并首先解决亚像素覆盖、透明度量化与 Canvas 像素严格一致性。继续缓存颜色或背景无法消除每次几十万条绘制命令的根本开销；不应承诺仅靠本轮方法进入 33ms。
