## 一、核心设计思路：卡牌 = 干预元胞自动机的四个维度

康威生命游戏本质上只有四个可玩维度，卡牌应该分别踩在维度上，形成完整闭环：

| CA 维度 | 卡牌类型 | 干预方式 |
|---------|---------|---------|
| **规则**（B/S） | 法则卡 | 全局改写生死规则几秒（你的原始想法） |
| **资源/能力**（能量、容量、部署） | 增益卡 | 强化玩家自身在游戏系统中的状态 |
| **棋盘状态**（已有细胞的增删改） | 道具卡 | 一次性直接修改棋盘局部状态 |
| **时间**（演化、衰老、占领） | 可散落进三类 | 加速/暂停/倒带局部演化 |

这正好对应你想到的三类卡，而且每一类作用层次不同：**法则卡影响全世界（双刃剑）、增益卡只影响自己（安全）、道具卡影响某个事件/位置（即时战术）**。三选一就变成了"稳、赌、战术"的抉择，而不是单纯数值大小对比。

## 二、具体卡牌设计（结合你的机制）

### 1. 法则卡 —— 改写 B/S 规则（全局）

**关键设计点：全局规则改变是一把双刃剑，玩家必须判断当前局势是否受益。** 这天然制造混沌。

示例：
- **「大爆发」** B3/S012345678：活细胞永生、死细胞疯狂重生 → 全场细胞海，很快撞上 24,000 容量上限，部署被锁死，战场从"博弈"变成"大洪水"
- **「大灭绝」** B3/S0：所有活细胞每代必死，只剩新出生的 → 双方大军瞬间清空，基地裸奔，必须立刻重建
- **「混沌纪元」** B36/S23：飞船变成随机游走，阵地难以推进
- **「寂静法则」** B3/S：没有存活规则 → 所有稳定结构消失，只剩振荡器闪烁
- **「倒退」** B/S23：没有出生 → 世界不可逆地收缩，兵力只减不增

**实现提示**：引擎 `step()` 目前硬编码 B3/S23，建议把 B/S 变成 `Game` 的当前属性（`this.birthRule` / `this.survivalRule`），法则卡激活时修改，到期恢复。好消息是 `RULES` 已集中配置，测试体系完整，参数化后每种法则都很好加测试。

### 2. 增益卡 —— 强化玩家自身

结合现有机制（能量 180 上限 / 回复 5/s、节点 +1/s、容量 6000、衰老 600 代、部署冷却）设计：

- **能量类**：「能量涌动」立即回满能量；「过载协议」能量上限 +60 并回满；「超频」回复翻倍 20 秒
- **部署类**：「闪电部署」下一图案免费且无视冷却；「工程展开」15 秒内部署消耗减半；「越界投放」允许在**相邻中立领地**部署一次（突破"只能从己方领地发射"的限制，非常战术性）
- **节点类**：「快速占领」30 秒内占领时间减半（3s→1.5s）；「领地固化」当前占领进度免疫争夺冻结
- **基地类**：「护盾」基地无敌 8 秒；「修复」恢复 60 耐久；「荆棘」基地受击半径 +6 持续 15 秒（报复性防守）
- **容量/衰老类**：「增殖协议」个人容量上限 +1500 持续 45 秒；「熵减」己方图案 30 秒内不会被休眠清理；「熵增」敌方图案提前进入衰老警告

### 3. 道具卡 —— 直接作用于棋盘

这是最有"卡牌感"的一类，也是最容易做出彩的：

- **「播种」**：在指定位置免费部署一个重型图案（高斯滑翔机枪/大飞船），无视部署范围限制但**不能在敌方核心 28 格内**（跟现有规则一致）
- **「净化」**：清除指定半径内所有活细胞（不分敌我）→ 用来清理逼近基地的大军，也可能误伤自己，需要选点
- **「星云」**：在指定区域生成一大团随机细胞 → 立刻制造局部混乱、阻断航道
- **「腐蚀」**：在指定小区域制造**局部法则**（如该区域 B/S 反转 5 秒）→ 把敌方推进中的飞船变成废铁
- **「侦察」**：8 秒内显示敌方全部活细胞位置（配合小地图高亮）
- **「降临」**：在敌方基地 28 格圈内**定点投放一次**（高危高回报，投放物下回合就会冲向基地）

## 三、三选一节奏设计建议

你的"第 3、5、7 分钟三选一"想法很好，建议按 **「稳定 → 战术 → 决胜」** 的梯度设计强度：

| 时间 | 定位 | 卡池倾向 | 法则卡时长 |
|------|------|---------|-----------|
| **第 3 分钟** | 开局发育期 | 能量/节点/部署增益为主，法则卡短时（3~4s） | 短促试探 |
| **第 5 分钟** | 扩张对抗期 | 道具卡占比提高，法则卡中时（5~6s） | 中期洗牌 |
| **第 7 分钟** | 决战期 | 高强度法则卡 + 直接伤害/清场道具 | 6~8s 决胜 |

**配套规则建议**：
- **手牌上限 1 张**：三选一后必须先在下一轮三选一前用掉，否则拿不到新卡 → 保证节奏紧凑，避免囤卡滚雪球
- **法则卡应显示明确的预告和倒计时**：顶部横幅「法则变更：大灭绝 — 剩余 5s」，让所有玩家（包括没抽到卡的）都能做出反应，混沌要有"可读性"才有趣
- **道具卡需要选点施放**：正好用你已实现的"卡牌拖出容器"交互 —— 把道具卡拖到战场上，目标位置高亮，松手生效（类似部署交互），这是天然的手牌 UI 延伸

## 四、实现层面的关键建议（针对你的架构）

1. **服务器权威**：所有卡牌效果必须在 `src/engine.js` / `server.js` 验证和执行（生成、清场、改规则），浏览器只负责 UI 和发送意图 —— 与你现有架构一致，防作弊
2. **协议扩展**：新增消息类型如 `card-draft`（发 3 张）、`card-pick`（选 1）、`card-play`（使用 + 目标坐标），沿用现有房间广播/增量同步
3. **卡牌数据表**：用类似 `config.json` 的 JSON 配置卡牌（id、类型、效果参数、持续时间），不要写死在代码里 —— 方便你后续调平衡，跟现有"规则全部集中在配置"的风格统一
4. **引擎参数化**：`Game.step()` 读取当前 B/S 规则 + 全局/局部法则状态（可维护一个 `ruleOverrides` 列表，支持多个法则叠加以制造更混沌的效果）
5. **测试先行**：每张卡都是一个确定性效果，非常适合写测试（如"大爆发时部署的图案不死亡"、"净化清空指定区域"），放进现有 `tests/` 体系
