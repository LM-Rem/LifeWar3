# GPU 演化、流畅渲染与逐代传输 Implementation Plan

**Goal:** 保持规则准确、逐代计算和逐代呈现，降低密集演化、小地图与网络的开销。

**Architecture:** Node.js 保持权威。服务器通过可选 Dawn/WebGPU 后端执行单代邻域与归属计算，CPU 继续结算基地、节点、卡牌和休眠；失败回退同一代 CPU。小地图复用世界纹理，网络压缩独立消息、背压后按顺序重放历史，绝不合并代数。

**Tech Stack:** Node.js、可选 webgpu 原生模块、WGSL、Canvas 2D、ws、node:zlib、node:test。

## 验收边界

- 本次用户要求优先；其他历史文档的像素一致、插入顺序等要求不作为新验收目标，但能保留的规则顺序仍保留。
- 不采用新优化建议中的跨代 last-write-wins 合并、降低发代频率、或有风险的休眠历史删减。
- GPU 必须验证整数规则、四阵营平票、边界、卡牌兼容与逐代对照。驱动不支持、局部规则暂不支持、设备失效时回退 CPU。
- GPU 是否默认使用取决于实机端到端测量，不以 shader 耗时冒充整代耗时。

## 1. 渲染

修改 public/minimap-cache.js、public/renderer.js：替换每细胞 Canvas 调用与贡献者 Set，复用 world 纹理缩绘；背景按状态更新，细胞按 boardRevision 更新。小地图及视口框约 10Hz，主画面仍逐代呈现。实测收包仍有显著 Map 开销后，增加 public/cell-store.js，用类型数组链表保留插入顺序并降低更新和内存成本。

验证：浏览器实绘、密集 50万/80万细胞耗时；核对阵营颜色、分区、基地、视口与空图。

## 2. GPU 演化

新增 src/evolution/gpu.js、gpu-worker.js；修改 backend.js、select.js、server.js。原生 WebGPU 放在 worker 中驱动，共享内存交换输入/结果；主线程保持现有同步事务语义，有限等待、异常回退，无跨代计算。先保留 CPU 候选顺序，以避免波及休眠与命令语义。

验证：GPU 可用性探测；CPU/GPU 连续逐代棋盘、活细胞顺序、变化包对照；局部规则与设备失败回退；50万/80万/100万负载整代测量。同步等待仍可能阻塞 I/O，作为本轮已知限制记录，不能宣称已完成多房间线程隔离。

## 3. 传输与容错

新增有界逐代消息历史；修改 src/server.js：慢连接重放独立代包，历史不足才快照；不改变客户端协议，不合并任何代。尝试有阈值、低压缩等级的 WebSocket 压缩；实测密集 CPU 场景发生积压，保留显式试用、默认关闭。静态资源 gzip、ETag 与缓存校验默认生效，保留编辑后失效。按房间隔离异常，故障房间停止推进并报告，其他房间继续。

验证：历史字节/代数上限、连续性、背压与恢复、v1/v2、gzip 解压和 304、真实 WebSocket。评估压缩率及 CPU 成本。

## 4. 回归与交付

运行 npm test、npm run test:replay、GPU 对照与密集基准、浏览器呈现验证。更新 README 和实施结果，明确已验证范围、实际 GPU 型号、性能收益与未解决项。保持用户工作区现有内容，不自动提交。
