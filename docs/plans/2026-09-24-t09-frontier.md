# T09：变化前沿实施与验收

日期：2026-09-24。前置版本：T13（aee889e）。目标是保持每代棋盘、alive 顺序、变化包顺序及既有呈现策略，减少低变化时重复计算。

1. **缓存与提交**：复用 counts/votes，另存结果和脏标志；所有决策结束后才应用变化。变化格自身及八邻域失效，所有生产写入经 recordChange 接入。
2. **规则失效**：全局 B/S、有效 birthPriority 改变激活全图；局部规则变化激活全部旧、新圆域并继续遵守后加入规则优先。原地修改 Set 也被检测。
3. **顺序与退路**：每代保留原有候选访问顺序、alive 重建和双缓冲提交。变化数超过 max(256, L/4) 放弃缓存，下一代用 sparse 完整重建；切换后端、批量导入也重建。auto 暂不改变。
4. **正确性**：512 组 B/S 掩码组合；1000 代外部写、局部/全局规则及同化变化；S0/B0、平票、32 位 stamp 回绕；生产阶段回放、AI、部署、净化圆边界、播种、休眠、消灭、重复换色及高变化退路。
5. **性能**：P01/P03/P04，每种模式五个独立进程、交替执行顺序、30 代预热及 100 代采样。比较 T13、当前 sparse、frontier、dense；补充静物海+飞船、1/8 局部规则与频繁规则变化。统计完整 step+v1 packet，记录环境、源码哈希、内存和原始采样。
6. **验收**：运行完整自动测试和 frontier 浏览器烟雾测试；根据实测决定是否晋级 auto。浏览器烟雾不替代密集场景 20Hz 逐代呈现认证。

实现及测量结论见 [T09 结果](../performance/t09-results.md)。
