# T11 密集重绘续优化

保持原有每个细胞的 Map 插入顺序、半透明 1×1 fillRect、Canvas 后端、图层顺序及小地图调度频率。不合并世代，不跳过应执行的绘制。

实施：

1. 冻结 T12 完成时的小地图与渲染器作为直接性能基线。
2. 预生成四种半透明颜色；完整重放中跳过连续同色的重复 fillStyle 设置。
3. 将细胞合成失效与背景失效分开。密集包和快照只失效合成及贡献索引；背景状态、尺寸、领地引用继续独立检查。仅尺寸改变时重设 Canvas 存储。
4. 验证密集→局部→绘制、快照、归属变化、尺寸变化与连续同色的失效边界。
5. 运行原有 188 项及新增 24 项像素对比、逐代呈现浏览器测试、单元测试，以及交错的五轮浏览器前后性能对照。计时同时报告提交耗时与 PNG 强制完成后的耗时，避免只转移异步栅格化开销。

探索记录：软件 Canvas 和 Path2D 合并在 Chrome 实验中出现像素差异，不采用；预绘制色块更慢；只交换互不覆盖像素的绘制未取得足够完成时间收益，也不采用。最终路径保持全部 primitive 顺序。

如果仍超过 33ms 小地图预算，明确记录缺口，不以减少绘制频率或降低画质达标。完成后报告源码指纹、环境、样本及回退方式。

已完成实施及验证，结果见 [实施报告](../performance/t11-dense-redraw-results.md)。
