# 网络追赶与紧凑位图应用 Implementation Plan

状态：已完成全部五步。最终自动化测试 186 通过、0 失败、4 跳过；浏览器对照与同机 GPU 基准完成。详见[实施结果](../performance/2026-09-29-network-pipeline.md)。

**Goal:** 不改变网络棋盘字节和逐代语义，改善短时积压追赶和客户端处理成本。

**Architecture:** 房间worker将演化与历史排空解耦，通过主线程发送完成后的有界缓冲通知继续重放；客户端保留经过完整验证的紧凑位图，在呈现代时直接应用。低频反馈仅用于诊断，不作为游戏权威或远端确认送达。

**Tech Stack:** Node.js worker_threads / ws、JavaScript 类型数组、Canvas、node:test、浏览器回归。

## 范围与决策

用户已授权计划与实施，当前工作区干净，直接完成。保持旧客户端、服务器alive与结算顺序、现有协议字节、历史/队列上限。暂不实施调色板、通用压缩、WebRTC、视野裁剪或客户端演化。

选用发送完成事件触发排空，避免固定高频轮询；保持每批字节预算，并新增包数预算，至少允许一个合法大包。发送回调只表示本地写出，不等于浏览器接收/呈现。ACK只解除对应输出锁，额外buffer通知不解除锁，避免重复并发输出；通知按房间合并并校验worker/连接身份。

位图解码新增compact选项，既有调用默认展开以保持兼容。新队列保留载荷引用和有界瓦片索引，计入内存。全部验证结束前不修改棋盘；呈现时仅提交实际变化。新能力采用无顺序棋盘集合视图，旧协议仍保留CellStore顺序。重置时恢复旧协议兼容集合。

反馈每500ms发送一次，包含epoch、接收代、实际绘制提交代、排队数量/年龄、最近解码/应用耗时；优先控制连接。服务器验证会话、epoch、范围和频率，保留最近一份诊断；不改变权威状态和历史删除条件。旧服务器不声明能力时不发送。

3. 新增进度反馈解析和过期/跨会话拒绝测试；修改public/app.js、renderer.js，新增src/client-progress.js并接入server.js。客户端报告只提供诊断。
4. 运行针对性测试、npm test、浏览器协议像素/重连对照；使用相同50万GPU负载对比紧凑路径与原展开路径，报告编解码、应用、队列内存和是否漏代，不承诺跨设备实时保证。
5. 更新README、协议说明和结果报告，记录启用方式、验证范围和局限。

## 验收

- 已校验的紧凑位图与展开位图重建同一棋盘/像素，损坏尾部也不能部分写入。
- 积压的大包无需额外演化tick即可按原代号排空；缓冲阻塞或无积压不形成消息自循环。
- 卡牌控制、重连、旧协议、同代修订、历史不足恢复保持正常。
- 反馈不接受跨epoch/连接和越界代号，不产生权威游戏副作用。
