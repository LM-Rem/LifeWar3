# 调度修复与小地图分项定位

目标：恢复轻负载配置代速，定位密集小地图实际成本；保持逐代规则、顺序和零像素差异。

1. 已在独立 Node 进程复现空 setInterval(50) 平均 62.30ms。比较相对间隔与单调截止时间调度，记录唤醒间隔、迟到、累计落后和事件循环延迟。拒绝忙等或修改全系统计时精度。
2. 用可注入时钟测试提前唤醒、正常抖动、回调耗时、长时间阻塞、过载与关闭。每个回调最多推进一代；长阻塞不无限突发追赶，放弃的时间债必须记录，不能跳 generation。
3. 小地图分项测量首次局部更新的索引构建、后续变更、贡献者重放、Canvas 提交、强制完成；保留纯遍历诊断与真实 Canvas 测量的区别。仅对确证热点修改，不继续叠加缓存。
4. 修复有收益路径后运行规则测试、冻结像素对照、单／四客户端 20Hz 普通负载与密集失败边界复测。保留未达标、队列和内存指标。

执行结果：以上四项已完成。本地普通负载恢复约 20Hz；索引首次构建改善约 8%–27%。145 项测试、276 项原始／协议画面比较、32 项 Map 比较通过；另有 24 对索引优化画面完全一致。密集单客户端仍未达标，全量 Canvas 重绘保持为未解决项。详见 [报告及复现方法](../performance/2026-09-25-scheduler-minimap.md)。

续诊断：带失效原因记录的 P03 重放定位到第 160 代的 11 个节点同时变更归属，触发 95 万细胞完整重绘（389ms）。这不是冗余失效。下一实验应针对背景变更后的有序重放，继续要求严格像素一致。
