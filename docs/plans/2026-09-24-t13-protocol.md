# T13 逐代无损协议实施记录

目标：减少实际全包大小，同时保留每代更新、旧客户端兼容与小地图插入顺序。

实施顺序：

1. 共享协议编解码模块：明确包头、ordered24、瓦片 sparse/dense、完整长度与输入校验。
2. 引擎新增 v2 封包，服务端连接前协商、roomEpoch、广播基准与按版本复用；快照后首代强制有序。
3. 客户端在现有逐代队列中校验版本、epoch、baseGeneration，计入解码内存；应用前完整验证有序新生。
4. 随机 1000 代与 v1 的棋盘/Map 对照，阈值、owner、畸形包、混合四客户端、背压和恢复测试。
5. 冻结参考渲染器像素对比、新客户端连接旧服务端、真实 WebSocket/RAF 回归；测量五轮编解码与全包/JSON 流量。
6. 根据性能门槛决定默认晋级。当前实现保留 v1 默认，v2 通过 `LIFEWAR_BOARD_PROTOCOL=2` 显式启用，不把压缩比等同于端到端达标。

新增像素夹具发现原小地图“密集区域局部裁剪”的像素差异，因此修正为原坐标完整栅格化后复制整数不透明瓦片；贡献者工作量超过全体细胞时直接全量重绘。此修正用于满足 T13 的画面一致性要求。

协议格式详见 [协议文档](../board-protocol-v2.md)。

已完成实施及阶段功能验证，性能与默认发布决定见 [实施及测试结果](../performance/t13-results.md)。
