# 选卡优先与 GPU 局部法则实施计划

目标：网络棋盘积压时仍能收到候选、提交选择并立即看到等待反馈；补齐 GPU 局部法则计算，保持服务器权威和逐代结算。

方案比较：仅加选中动画不能解决回执排队；完整房间 worker 可以减少主线程阻塞但迁移范围较大。本阶段采用独立卡牌控制 WebSocket、独立卡牌状态和 GPU 局部规则缓冲。房间 worker 留作下一阶段，不宣称本次解决所有 CPU 长任务。

1. 服务端控制连接用现有会话令牌绑定，只允许选牌、出牌和 ping；主连接关闭即失效。卡牌私有状态独立序号发布，绕过棋盘背压与呈现队列。旧客户端保持兼容。
2. 客户端按 epoch/序号接收最新卡牌状态；点击即时显示提交中并禁止重复，失败恢复。控制连接不可用时回退主连接，断线重连重新绑定。
3. GPU 增加有界局部圆形法则缓冲，后添加规则优先，保留同化、边缘、失败与超时 CPU 回退。
4. 验证真实 WebSocket 背压、私有状态、断线解绑、重复请求和 GPU/CPU 一致性；运行完整测试与回放，记录硬件测试实际可用性及限制。

不改变运行默认 GPU＋v2，不合并棋盘代数，不暂停服务器演化。低带宽仍有物理吞吐限制，独立连接无法保证任何带宽下的固定延迟。
