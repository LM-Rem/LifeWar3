# 压测基线与局部调色板实施计划

**Goal:** 先采集高变化P04、低变化P03、空间交界P05的瓦片分布，再实测编码字节，达到收益门槛后接入协商。

**Architecture:** 复用32×32瓦片和紧凑应用路径。encoding 4增加局部阵营掩码，单阵营0bit、双阵营1bit，三/四阵营保留原2bit。每瓦片和完整包选择更小者。保留逐代同步与恢复边界。

**Tech Stack:** Node.js、node:test、ws、浏览器模块。

1. scenarios.mjs增加确定性交界夹具；palette-bandwidth.mjs预热25代测量20代，保存瓦片阵营数/变化密度、增量/快照字节、编解码耗时和完整棋盘验证。
2. bitmap-codec.js与board-protocol.js增加默认关闭的离线候选。门槛：目标场景完整包至少省10%，低变化不增大，所有重建一致。四阵营混杂允许零收益。
3. 通过后在engine/server/room-runtime/app/generation-queue接入paletteTiles独立协商及缓存变体。未声明4不请求，未请求不发送。
4. 增加0/1bit、边缘、删除、快照、随机连续代、紧凑/展开、非法掩码/填充/截断、能力隔离测试。运行npm test和浏览器像素/协商验证。
5. 增加本机浏览器网络基线与诊断采样，记录吞吐、进度、发送缓冲、队列、RTT与恢复。真实线路后续采集（用户已选择）；不得把本地结果描述为公网保证。
6. 更新协议、README和报告，提交可复现命令及原始样本。

本轮不扩展变化掩码与状态JSON。低变化不增加字节；编码耗时单独报告。用户已授权直接实现，不另开任务或提交git。
