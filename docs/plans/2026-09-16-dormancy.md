# 600 代休眠清理 Implementation Plan

**Goal:** 原地短周期结构连续休眠 600 代后由服务器清除，最后 100 代预警。

**Architecture:** 32 格分块、两格观察边界和周期 1–8 指纹筛选；相邻非空观察块组成保守清理组，整组达到阈值且逐格复核后删除。服务器使用演化代数计龄，通过现有细胞增量同步删除，通过 state 同步预警。

**Tech Stack:** Node.js、TypedArray、WebSocket、Canvas。

1. 新建 src/dormancy.js，将实验检测器实现为生产模块，加入整组复核、部署失效和 600 代清理。
2. 修改 src/engine.js，演化与目标结算后检测清理，更新人数统计和网络增量，公开预警与规则。
3. 修改 public/renderer.js 与教程，绘制休眠预警并说明 600 代规则。
4. 新建 tests/dormancy.test.js，验证静物、振荡器、跨块、移动图案、干扰、节点保留和增量一致性。运行 npm test，增加生产实现基准测试并记录性能。

限制：同组中的活动可推迟静物清理；超过 8 代的周期不保证识别。此保守策略优先避免误删和振荡器残片。无暂停或真实时间计时器。
