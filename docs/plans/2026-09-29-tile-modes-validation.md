# 全同色块、行游程、变化掩码验证计划

**Goal:** 用完整编解码而非大小估算验证三个候选模式，并给出是否值得接入的结论。

**Architecture:** experiments内独立实验编码（encoding250，不加入生产协商）。复用32字节头及32×32瓦片，保留现有palette编码作整包回退。SOLID=1字节owner；RLE=uint16段数＋每段uint16(length-1 | owner<<10)，按有效格行序允许跨行连续；MASK=128字节变化位＋每个变化格3bit最终owner。前两者完整替换瓦片，MASK仅改指定位置。沿用严格计数、坐标、padding验证及紧凑索引。

**Tech Stack:** Node.js、node:test、浏览器模块、Playwright（已有运行时）。

1. 独立实验编解码：experiments/tile-modes-codec.js，不改public/src生产代码。
2. tests/tile-modes.test.js：全死/全活/边缘、RLE跨行与长度、掩码3bit跨字节、增量/快照/同代修订、非法数据不产生部分写入、随机连续代及旧包回退。
3. tests/performance/tile-modes.mjs：P03/P04/P05预热25代、测20代；补充每瓦片5/12.5/25/50%随机变化（单阵营与四阵营，刻意非演化的编码夹具），以及条带与全同色场景。单独SOLID/RLE/MASK与组合及基线对照。完整包字节、模式数、编码/紧凑解码/应用p50/p95、重建hash、原始样本保存。
4. 浏览器运行同一实验模块，比较紧凑解码和棋盘应用，不能用Node时长代替浏览器时长。生产渲染未接入，结果不作为端到端绘制保证。
5. 通过条件：所有棋盘完全一致、每包不增大；目标场景节省≥10%。额外计算耗时单独评估，不因字节收益自动晋级生产。说明低变化小包、满噪声场景是否值得做候选扫描。
6. 更新结果文档与README验证入口，运行针对性测试及必要回归。真实线路与协议协商不在本轮验证范围。

已完成：独立完整编解码、21场景/4200包、840次浏览器逐代校验、全套测试与结果报告。保持生产协议不变；组合原型因高变化无收益开销不晋级默认。
