# 卡牌系统：分析、改进与实现

2026-09-22。本文描述当前落地规则，原始 `卡牌设计.md` 保留作为设计素材。

## 设计修正

- 保留法则（全局规则）、增益（自身能力）、道具（局部棋盘）三个维度。每轮候选各含一张，避免三张纯数值卡让抉择失去意义。
- `B3/S0` 中 S0 表示零邻居细胞存活，不是全部死亡，因此将原「大灭绝」改名「孤岛法则」，保留该独特规则。真正不允许任何旧细胞存活的是 `B3/S`。
- 大爆发采用文案中的 `B3/S012345678`。永恒洪水明确为 `B12345678/S012345678`，无邻居的空白处不会凭空出生；配置不支持 B0，避免稀疏模拟无法完整处理且新生阵营无来源的问题。
- 卡牌持续时间和征召时间按服务器现实时间计算，不随 `config.json` 中的 hz 改变。常规生命演化、资源基础回复和占领仍按代进行。
- 全局法则先预告 1 秒，再生效。已有法则在预告期间继续运行，新法则生效后替换旧法则；预告期间再次施放则以最后一次预告为准，已使用的卡牌不返还。不把多个 B/S 集合隐式合并。局部法则优先于全局，重叠区域以最后施放者为准。
- 能量涌动根据当前实际上限回满；临时容量到期不强删现存细胞，只限制后续出生和部署。
- 当前战场已经公开全部细胞，因此不增加无实际收益的「侦察」卡。敌方衰老加速暂不加入：休眠检测以混合阵营的空间块为单位，直接加速会造成所有权与预警歧义；战术清场由净化和腐蚀承担。
- 局部暂停/倒带会涉及跨区域邻居、核心伤害和占领结算的回滚，本版不加入。播种选用固定重型飞船而非永久产出的滑翔机枪，以控制无领地部署的收益。

## 征召与手牌

1. 默认第 3、5、7 分钟分别从 early、mid、late 卡池抽取。
2. 每名存活玩家独立抽取法则、增益、道具各一张，选卡窗口 30 秒。
3. 手牌上限一张。主动选择新卡会替换旧卡，弹窗提前说明这一点；超时有旧卡则保留，无旧卡则自动选择本轮增益卡。
4. AI 自动选卡；断线或淘汰玩家不会阻塞后续轮次。淘汰时清理手牌、个人增益与待选资格；已经释放的全局/局部法则持续至各自到期。
5. 手牌与候选只发给所属玩家。已经生效的增益、全局/局部法则属于公开战场状态。
6. 刷新重连恢复手牌、当前征召、法则预告、持续效果及其截止时间；不会重新计算持续时长。

## 结算与边界

- 同一玩家同种增益刷新持续时间，不叠加数值；不同种增益可以组合。免费部署优先于折扣，折扣按整个去重图案向上取整。
- 免费部署仍检查边界、己方领地、敌核心禁区、碰撞、个人和全局容量；失败不消耗次数。部署冷却已集中在引擎，玩家与 AI 走同一条路径。
- 越界投放只允许进入与己方领地**共享一条边**的中立节点分区，不包括只接触顶点、非相邻中立区、敌区或被毁的基地分区。在己方领地部署不消耗该次数；跨区成功才消耗。占领仍须持续接触节点。
- 领地固化只有己方已建立的占领进度、且范围内仍有己方细胞时生效；不凭空建立争夺中的占领资格。
- 护盾使核心免伤，接触的敌细胞仍被消耗；修复不能超过配置耐久上限，也不能复活。
- 熵减仅阻止己方细胞被休眠清理，不能抵抗生命规则死亡、核心接触或净化。
- 净化不分敌我，不直接伤害核心、不直接改节点归属。圆域可被地图边界裁剪，中心必须在地图内。
- 播种和星云免费、允许跨领地，但必须满足地图与容量校验。播种不能覆盖活细胞；星云只向空格随机生成，若随机结果为空且存在空格则至少生成一格。
- 生成类道具保护半径使用 `max(28, baseHitRadius)`，包含边界。星云整个圆域不得触及敌核心保护区；播种逐细胞检查。这样调大基地受击范围时也不会出现直接投放伤害。
- 道具目标非法、图案冲突或容量不足时，整次操作不修改棋盘、不消耗手牌。所有增删通过同一二进制增量同步。
- 局部法则最多同时8个；预告/持续效果在下一次引擎处理时到期，误差最多约一代。服务器卡顿期间不执行额外补偿演化。

## 操作与界面

- PC 保留按下拖动；触屏保留先点选、再拖动选中卡牌，其他区域用于原生列表滚动。
- 拖动时服务器状态更新不会重建相同手牌；只有手牌实际变化或对局重置才清理交互。
- 法则/增益卡拖出仓库即发送使用请求。道具卡拖出后进入选点模式，显示作用圆域，播种同时显示图案；点击战场施放，右键、Esc或「取消选点」退出。
- 选点失败保留选点模式，便于重新选择；成功由服务器确认后退出。
- 战场显示法则预告与倒计时、个人增益剩余时间、下一轮征召时间、局部腐蚀区域和核心护盾。
- 部署预览使用服务器同步的实际费用倍率、个人容量和越界投放权限；能量条显示临时上限与实际回复倍率。

## 配置与维护

`public/cards.json` 是卡牌参数的唯一数据源：`drawSeconds`、`draftSeconds`、`lawWarningSeconds` 和 `cards`。修改后重启服务器并刷新客户端。`effect` 使用 `kind` 分派，秒数为 `seconds`，范围为 `radius`，增益通过 `stat` 指定；名称和说明也在同一文件中维护。

`public/cards.js` 负责前后端共用的加载、校验与类型辅助函数。新增同类卡牌可只改 JSON；新增效果类型仍需实现引擎分支、预览和测试。配置错误会明确报错，禁止重复 ID、非法 B/S、缺少类型的卡池和越界参数。

`npm test` 通过 `tests/setup.js` 指向独立的空配置文件，使用规则默认值，不修改实战 `config.json`。`LIFEWAR_CONFIG_PATH` 可指定其他规则配置文件（服务器端环境变量）。

## 验证

- `npm test`：66 项通过，0 失败。浏览器实测完成选牌、法则拖出使用、道具选点施放，以及 390×844 窄屏候选牌布局；控制台无警告或错误。触屏逻辑有自动化回归覆盖，尚未进行手机真机验证。
- 自动化覆盖：全部法则的 B/S 判定、现实时间/替换/到期、增益组合、单次效果原子性、共享边邻接、核心保护、容量回落、播种增量一致性、三轮征召、超时、淘汰、私有状态、真实 WebSocket 重连、全部卡牌 AI 使用，以及 PC/触屏拖动回归。
- 性能基准包含普通演化与二进制打包，不代表移动端 GPU、网络压力或长期对战平衡。
- 卡牌强度为首版参数，仍需多人实战调平衡，尤其是无限存活法则、越界投放与一次性生成细胞的组合。
